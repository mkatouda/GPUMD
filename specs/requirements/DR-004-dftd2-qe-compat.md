# DR-004: QE-compatible parameter table, plain cutoff and speed-up for `dftd2`

- Status: Approved by the human on 2026-11-06 (implementation waits for DR-003 to be merged into develop, D1)
- Design: `specs/design/DES-0004-dftd2-qe-compat-plan.md`
- Origin: request from the PTFE NEP/qNEP project (`/home/katouda/work/dielectric-response_pj/tmp/request_to_fork/REQUEST_dftd2_qe_compat.md`, 2026-11-06)
- Related: DR-002 (dftd2; its decisions D1-D6 stay in force unless stated here), DR-003 (supplies the `r0ab` table, VER-0023; priority: DR-003 first)

## Requirement
`dftd2` shall additionally support (R1) the pair parameters used by Quantum ESPRESSO's
`dftd3_version = 2`, (R2) a plain (hard) truncation, and (R3) a shorter run time, without
changing any existing `dftd2` input or result.

QE `dftd3_version = 2` is "D2 form with D3 tables", NOT Grimme 2006 D2 (to be confirmed against
the QE sources, DES-0004 Phase 0):
E = - s6 sum_{i<j, all images, r <= rc} C6_ij f(r) / r^6,
f(r) = 1 / (1 + exp(-alp6 (r / (rs6 R0_ij) - 1))), alp6 = 20, rs6 = 1.1 (PBE s6 = 0.75),
C6_ij = D3 `c6ab(Zi, Zj, 1, 1, 1)` (first reference point of both atoms, CN independent),
R0_ij = D3 `r0ab(Zi, Zj)` (Angstrom).

## Decisions taken by the human (2026-11-06)
D1. Order: DR-003 (D3(0)) Phase 4 is finished first; this requirement waits. DR-004 uses the
    `r0ab` table and generator of DR-003 (VER-0023), so DR-003 must be merged into `develop` first.
D2. Parameter table: a built-in `r0ab` is used; a user-supplied pair table is not part of this
    requirement.
D3. QE version (revised 2026-11-06 after the source and release-note comparison): QE 7.2
    (tag qe-7.2, commit b4c5e8de; the requester's version) is the reference. The D2 definition
    is numerically identical in qe-7.2, qe-7.3..7.6 and the local development HEAD
    (7.6-515, `/home/katouda/build/q-e`): `dft-d3/pars.f90` (C6) is byte-identical; the
    `version == 2` block of `setfuncpar` (rs6 = 1.1, s18 = 0, alp = 20, per-functional s6) and
    `setr0ab` differ only by the `_wp` literal suffix at HEAD; the cutoff is `sqrt(9000)` bohr
    in all; the differences 7.2 -> 7.6 are MPI communicator handling, error calls, build files
    and argument cleanups (VER record in DES-0004 Phase 1). The release notes of 7.3-7.6
    contain no DFT-D3 entry (the D3 items, e.g. the Ba r2r4 fix, belong to <= 7.2 and affect
    C8, not D2). So `table qe` covers QE 7.2 and later without a version switch. A later QE
    change would be detected by re-running the Phase 1 comparison, and handled by a new `table`
    value, not by changing `qe`. Tools: local clone `/home/katouda/build/q-e`, built binaries
    `/home/katouda/bin/qe/bin`.
    QE input documentation (INPUT_PW) calls `dftd3_version = 2` "Original Grimme-D2
    parametrization" and states that the three-body term is always off for it. The requester
    found numerically (printed digits, stress 0.01 kbar, PTFE) that C6 and R0 come from the D3
    tables; the Phase 1 check against the source decides, and the manual says so.

## Decisions P1-P5 (proposed in the draft, approved with this requirement on 2026-11-06; P1 still needs ADR-0004)
P1. Syntax: `dftd2 <s6> [<rc>] [table grimme2006|qe] [trunc sf|plain]`; options in any order after
    `s6` / `rc`; defaults `table grimme2006`, `trunc sf` (= current behavior, `rc` default 30 A);
    `rc` must be given explicitly when `table qe` or `trunc plain` is used (ADR-0004 item 6,
    approved 2026-11-06). Decided in ADR-0004 (accepted).
P2. With `table qe`, rs6 = 1.1 and alp6 = 20 are fixed (as QE PBE); `s6` stays user-given (DR-002 D2).
    The damping in the kernel is r / (rs6 R0_ij) with R0_ij from `r0ab`; kernel unchanged except
    for the table content.
P3. Elements: `table qe` is limited to Z <= 86 (as DR-002 D5 and DR-003 D5; the D3 `r0ab`
    and C6 values for Z >= 87 are unverified, VER-0023). An atom type with Z >= 87 present in the
    structure is an error naming the element(s).
P4. `trunc plain`: phi(rc) and phi'(rc) of the pair table are set to 0 (hard cutoff, like
    `dftd3`). The energy jump at rc and its NVE effect are documented. It applies to both tables.
P5. `dftd2` stays mutually exclusive with `dftd3`; scope (NEP variants) as DR-002 D4.

## Acceptance criteria
- AC-1 (verification): energy, force and virial agree with the numpy reference
  (`reference/d2_reference.py`, double; and an independent check against QE 7.2 printed D2
  energy, forces, stress for C and F, as supplied by the requester) within the DR-002 AC-1
  tolerances, for `qe/plain`, `qe/sf`, and `grimme2006/plain`; four PTFE structures
  `ptfe_cryst157_vol*`, `rc = 12`.
- AC-2: `grimme2006/sf` (default, explicit or not) is bit-identical to the pre-change binary.
- AC-3: the `r0ab` and C6 used for `table qe` equal the QE 7.2 sources entry by entry for
  Z <= 86 (generated by script; any difference between QE 7.2 and dftd3-lib tables is listed,
  not hidden); the pair values for C-C, C-F, F-F equal those in the request (C6 49.113 / 20.2827 /
  9.6916 Eh bohr^6, r0ab 2.9103 / 2.4770 / 2.2996 A).
- AC-4: replicated supercells (e.g. 4x4x2) give the same energy per atom and per-atom forces
  (large-box regime), and a thin box (< 2 rc) is handled (as DR-002).
- AC-5: finite-difference force and virial consistency for `qe` and `plain`; NVE conservation
  with `plain` reported as informative.
- AC-6: input errors: unknown table or trunc value, duplicate option, Z >= 87 with `table qe`.
- AC-7 (performance, informative): R3 below; a result is reported even when the target is missed.
- AC-8: manual (`doc/`, `docs_ja/`), traceability, examples updated; the manual states that QE
  `dftd3_version = 2` is not Grimme 2006 and recommends recording and matching table and
  truncation between label generation and MD.

## R3 speed (separate gate, does not block R1/R2)
Request: for N >= 40,000, `dftd2 ... 12` should be no slower than `dftd3 pbe 12 6`.
Hypothesis of the requester (UNVERIFIED): the 13 double accumulators per pair (e_i, fx, fy, fz,
9 virial components) dominate on GA102 (FP64 = 1/64 FP32). Past data: positions are already float
(VER-0009); accumulator precision was never isolated. Order of work: (a) timing-only variant
with float accumulators; (b) only if it is faster by >= 20% at large N, a conforming variant
within DR-002 AC-1 (float per-thread partial sums, one conversion to double; possibly compensated);
(c) 6 symmetric virial components. Production GPUs (A100, sm_80) are measured by the requester;
here only sm_86 is available.

## Out of scope
Half neighbor lists with atomics, multi-GPU, analytic tail corrections, user pair tables, Z >= 87.
