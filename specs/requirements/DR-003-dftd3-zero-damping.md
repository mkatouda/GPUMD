# DR-003: DFT-D3 with zero damping, D3(0)

- Status: Approved by the human on 2026-11-06 (created 2026-11-06)
- Design: `specs/design/DES-0003-dftd3-zero-damping-plan.md`
- ADR: `specs/decisions/ADR-0003-dftd3-damping-keyword.md`
- Related: DR-001 (D3 GPU performance; BJ path must stay numerically unchanged), DR-002

## Requirement
The `dftd3` keyword shall support Grimme's zero-damping D3(0) in addition to the existing
BJ damping, for NEP and NEP_Charge (same scope as the current BJ support).

E = - sum_{i<j} [ s6 C6_ij f6(r) / r^6 + s8 C8_ij f8(r) / r^8 ],
f_n(r) = 1 / (1 + 6 (r / (sr_n R0_ij))^(-alpha_n)), alpha_6 = 14, alpha_8 = 16, sr_8 = 1.
(To be confirmed against Grimme et al., J. Chem. Phys. 132, 154104 (2010) in DES-0003 Phase 1.)

## Decisions taken by the human (2026-11-06)
D1. Syntax: `dftd3 <functional> <rc_potential> <rc_cn> [zero|bj]`. The optional last token
    selects the damping; the default is `bj`, so every existing input behaves exactly as before.
    Any other 5th token, or more than 5 tokens, is an input error.
D2. Functionals: PBE is the first priority. Then revPBE, BLYP, B3LYP, TPSS (main set). The
    full D3(0) functional table is required before an upstream PR (Stage B).
D3. No user-supplied s6/s8/sr6 parameters in this requirement.
D4. Scope: NEP and NEP_Charge only. `NEP_Charge_VDW`, `qnep3_vdw`/`nep_vdw` and multi-GPU
    keep rejecting `dftd3`. `dftd3` and `dftd2` stay mutually exclusive.
D5. Elements (decided 2026-11-06 after VER-0023): D3(0) is limited to Z <= 86 (H-Rn).
    For Z = 87-94 the dftd3-lib and simple-dftd3 tables disagree (r0ab up to 29%, C6 about
    5%; VER-0023) and the correct values are unverified. If the structure contains an atom
    type with Z >= 87 and zero damping is selected, `dftd3` stops with an error naming the
    element(s); no silent zero or fallback. Applies to zero damping only; BJ is unchanged.
    "Present" means atom types actually present in the structure, not the elements listed in
    the model (NEP89 lists Ac-Pu, so a model-based check would always fail). Decided 2026-11-06.
    Revisit (extend to Z <= 94) only after a check against the primary source (DFTD3 V3.1
    `pars.f` or the paper SI), as a separate decision.

## Acceptance criteria
- AC-1 (verification): energy, force and virial agree with simple-dftd3 (zero damping, two-body,
  same functional) within the tolerances of ADR-0002 (relative 2e-6 of the D3 energy/virial scale;
  force limit as in DR-001 AC-1), for PBE and each main-set functional.
- AC-2: force and virial agree with finite differences of the energy; NVE energy conservation
  is not worse than the BJ path.
- AC-3: `dftd3 <f> <rc> <rc_cn>` and `... bj` give results bit-identical to the pre-change binary.
- AC-4: unsupported functional for the chosen damping stops with an error naming the damping and
  the functional; no silent fallback to BJ.
- AC-4b: Z >= 87 with zero damping is an error naming the element(s) (D5).
- AC-5: no overflow/NaN for very small r (r << R0) and for float; small-box and large-box paths agree.
  AC-5 limitation (decided 2026-11-06 after VER-0024 and the numerical review): "small-box and
  large-box paths agree" is met at the ADR-0002 caps for the reference systems except
  heavy_cluster (replicated into the large-box branch: virial difference 1.14 x cap with the
  adopted code; 1.40 x cap when the large-box CN kernel is also made double, which was tried and
  reverted). The same system shows 1.72 x cap for BJ (develop code, unchanged by DR-003), so this
  is a pre-existing difference between the two paths for systems with a small reference virial and
  strong term cancellation (relative cap very tight in absolute terms), not caused by zero
  damping. Its origin is not identified (candidates: float rounding of positions in the
  small-box neighbor list, float differences and `apply_mic` in the large-box path). It is
  recorded as a known limitation; investigation is a separate task (DR-001 area). Accepted as an exception by the human on 2026-11-06 (traceability status: implemented with this AC unmet).
- AC-6: performance of the zero path is within 10% of the BJ path on the DR-001 benchmark
  (informative; BJ must not slow down).
- AC-7: the parameter tables (r0ab, D3(0) functional parameters) are generated by script from the
  primary source and cross-checked entry by entry (VER record). Nothing typed by hand.
- AC-8: manual (`doc/`, `docs_ja/dftd/`), `specs/traceability.yaml` and examples updated.

## Downstream need (reported 2026-11-06 by the GPUMD-polymer-apps agent; resolves OQ-1)
- Damping: zero (QE `dftd3_version = 3`), functional PBE. Expected values s6=1.0, s8=0.722,
  sr6=1.217, alpha6=14, sr8=1.0 are a claim to be verified against the primary table in
  DES-0003 Phase 1 (not taken as a reference value).
- Evidence (downstream, QE 8.0dev, SG15 ONCV, 140 Ry, Gamma, C12F48 60 atoms): D3 energy
  QE -0.4617 eV, simple-dftd3 PBE-zero -0.4668 eV, BJ -0.8706 eV. This is a consistency
  observation, not validation of this implementation.
- Use: D3(0) is added back in MD to NEP/qNEP trained on D3-subtracted labels.
- Three-body: QE default `dftd3_threebody = .TRUE.`; the downstream estimate of the ABC term is
  about 1% of D3 (5 meV for 60 atoms; not measured separately). Decision (downstream, 2026-11-06):
  the two-body term is sufficient for the prototype stage.

## Out of scope / limitations
- The three-body (Axilrod-Teller-Muto) term is NOT implemented, as for BJ. The manual states
  that D3(0) here is two-body only and differs from QE's default (three-body on) by the ABC term.
