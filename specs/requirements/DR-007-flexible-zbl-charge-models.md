# DR-007: flexible ZBL (`zbl 0 0` + per-pair parameters) must work for charge models (qnep1/2/3), including `charge_transfer`, in `nep`, `gpumd`, and replica dynamics (`multi_replica` inside `gpumd`)

- Status: **Approved 2026-11-20** (human approved the defaults of all 8 open points; text as revised 2026-11-18 for the merged tree, develop `fc67a8cc`, contains upstream 5c67f365; original draft 2026-11-13 by the requester's verification side). Implementation: stages 1-5 on branch `dr007-flexible-zbl` (VER-0040, 2026-11-21); AC-8 open. Requester: at a meeting on 2026-11-20 the requester delegated the review and approval of this revision to the human (reported by the human; no written record in the repository). AC-8 still needs the requester's v5.9.1 files.
- Origin: requester's decision (2026-11-13; per-pair ZBL adopted for the production NEP after requester-side training runs, see the request, section 1): use the fork (`charge_transfer` qNEP for the dielectric response, fast DFT-D3/D2) for PTFE (C, F), which needs per-pair ZBL; no inquiry or PR to upstream; implement in the fork.
- Related: DR-005 / ADR-0006 (`charge_transfer`), ADR-0007 (this change's decision record), VER-0022 (upstream merge that brought the restriction), VER-0037 (merge of upstream 5c67f365: new file structure, legacy formats removed, replica inside `gpumd`), upstream `4508bba2` ("simplify kernels") and `dbecce90` ("restric flexible zbl", PR #1866).
- Upstream behavior is a contract: this requirement deliberately **diverges** from upstream (upstream accepts flexible ZBL only for `model nep` since 2026-10-29); ADR-0007 is required. The behavior it restores is that of upstream v5.9.1.

## Problem (code reading of the merged tree, develop `fc67a8cc`, 2026-11-18; the 2026-11-13 findings were made on `5de76eb5` and fork `8afa074`)
Charge models (`qnep1`, `qnep2`, `qnep3`) reject flexible ZBL. In the merged tree the checks and assumptions are at:
- `src/utilities/nep_io/nep_model_file.cu:246-249` (reader of the new format: "Flexible ZBL is only supported for model nep."; typewise-factor exclusion at 252; `zbl_parameters` block count `10*T(T+1)/2` after it);
- `src/utilities/nep_io/nep_model_file.cu:314-336` (`validate_md`): lines 326-329 refuse `charge_transfer` + flexible ZBL ("never coexist"), line 336 limits flexible ZBL to 550 values (10 active elements);
- `src/main_nep/common/nep_parameters.cu:110` (trainer: `flexible_zbl && model_name != "nep"`); `src/main_nep/common/nep_io.cu:376-377` (writer: block order `parameters`, `q_scaler`, `phi_parameters`, `zbl_parameters`, comment "never coexist") and the reader/compare paths at 460-465, 638-643;
- `potentials/nep/nep_model_converter.py:129` (legacy `nep4_zbl_charge*` with `zbl 0 0` rejected) and the legacy value order at 197-222; `potentials/nep/nep_model_format.md` lines 228-238, 499-502, 575-576, 717 (statements "only for model nep");
- no flexible-ZBL kernels in the charge force classes: gpumd `src/force/nep_charge/nep_charge.cu` (universal ZBL only, around 1100-1160) and `nep_charge_small_box.cuh`; replica `src/force/replica/replica_nep_charge_model.cu` (universal ZBL only, lines 115-136) and its kernels. (The energy-NEP classes `src/force/nep/`, `src/force/replica/replica_nep_model.cu:71-79,194`, `src/mc/nep_energy.cu:79-86`, `src/phonon/nep_analytic_hessian.cu:167` do have flexible ZBL.) Upstream removed them from the charge classes in `4508bba2` and restricted the model list in `dbecce90` (PR #1866).
- The legacy (old-format) reader of `gpumd` no longer exists: upstream 5c67f365 removed nep.txt formats 1-6. v5.9.1 old-format flexible qNEP files can only be used after conversion.
- The shared trainer kernels (`src/main_nep/common/nep_common.cu`) still support `zbl.flexible`.

## Requirement
R1. `gpumd`: `potentials/nep/nep_model_converter.py` converts old-format `nep4_zbl_charge1/2/3` with `zbl 0 0` (written by v5.9.1) to the new format (`model qnep1/2/3`, `zbl 0 0`, `zbl_parameters`, `10 * T(T+1)/2` values, pair order and index as in `potentials/nep/nep_model_format.md` section 4.3); `gpumd` applies the per-pair parameters in both the large-box and small-box ZBL kernels. The converted model gives the same energy, forces, and virial as v5.9.1 (AC-8). (Direct reading of old-format files by `gpumd` no longer exists after the merge of upstream 5c67f365 and is not restored.)
R2. `gpumd`: new-format `qnep1/2/3` with `zbl 0 0` and a `zbl_parameters` block are accepted by the reader (`nep_model_file.cu`), `validate_md`, and the compact (active-element) path (`nep_model_file_compact.cu`: the per-pair block must be reduced to the active elements).
R3. `nep`: `zbl.in` flexible ZBL is accepted for qnep1/2/3 (with and without `charge_transfer`); `nep.txt` is written with `zbl_parameters` (count `10 * T(T+1)/2`) and read back (prediction, restart, existing-model checks).
R4. `charge_transfer` and flexible ZBL can be combined in `nep`, `gpumd`, and replica dynamics: the refusal in `validate_md` (`nep_model_file.cu:326-329`) and the comments that say they never coexist are removed. New-format blocks are named, so their file order does not matter (the `nep` writer order is `parameters`, `q_scaler`, `phi_parameters`, `zbl_parameters`); the converter keeps the legacy value order `parameters`, `q_scaler`, `zbl_parameters`, `phi`; charges and BEC do not depend on ZBL.
R5. Replica dynamics (`multi_replica`; code in `src/force/replica/`, a separate copy of the force code) mirrors R2 and R4 (the combination refusal is removed there too). The replica computes no BEC.
R6. Nothing else changes: ordinary NEP, qNEP with universal ZBL or without ZBL, `charge_transfer` without ZBL give bit-identical energies, forces, virials, charges, and BEC to the pre-change binary; `nep_dipole`, `nep_polarizability`, NEP-spin keep rejecting flexible ZBL; flexible ZBL with a typewise factor stays an error; more than 10 active elements (550 values) stays an error.
R7. Documentation and tools are updated: `doc/nep/input_parameters/zbl.rst`, `use_typewise_cutoff_zbl.rst`, `potentials/nep/nep_model_format.md`, `potentials/nep/nep_model_converter.py` (flexible ZBL for charge models, also together with `charge_transfer`), the `charge_transfer` manual page (`doc/nep/input_parameters/charge_transfer.rst`).
R8. A guard test fails if a later upstream merge brings the restriction back for the models in R1-R4 (all three places: reader, `validate_md`, trainer `finish_reading`). Note: after the 2026-11 release cleanup, upstream's direction is to keep the restriction, so conflicts are expected at each merge.

## Acceptance criteria
- AC-1 (premise, stage 1). In the ordinary NEP path, a flexible ZBL whose per-pair parameters equal the universal ones (inner/outer equal for all pairs, a1..b4 = 0.18175, 3.1998, 0.50986, 0.94229, 0.28022, 0.4029, 0.02817, 0.20162) reproduces the universal-ZBL energy, forces, and virial. Observed difference recorded (bit-identical or the float-noise level); the later tolerances are derived from it, not assumed.
- AC-2 (analytic, stage 2). For qNEP: the same equivalence as AC-1; an independent float64 dimer reference (formula in the request, appendix A) is matched within 1e-6 relative in energy and 1e-5 relative in force; finite-difference force and virial tests pass at the gates of the existing charge_transfer tests, with no loosening; large-box and small-box kernels agree.
- AC-3 (training and IO, stage 3). `nep` trains a few generations with `zbl.in` for qnep2/qnep3 with and without `charge_transfer`; `nep.txt` contains `zbl_parameters` with the right count; prediction mode reads it; `nep` and `gpumd` predictions agree (`test_nep_model_consistency.py` style); the converter round-trips an old-format flexible qNEP file to the new format and back.
- AC-4 (charge_transfer, stage 4). With `charge_transfer` + flexible ZBL: charges and BEC are bit-identical to the same model without ZBL; force/virial finite differences pass; the field-conservation test passes.
- AC-5 (replica, stage 5). `multi_replica` runs the combination and agrees with `gpumd` by the displacement-identity gate of `tests_pytest/test_replica_charge_transfer.py` (self-calibrated against ordinary `gpumd`; RMS dF <= 1e-4 eV/A, dE/N <= 1e-4 eV/atom; no BEC, no virial gate unless decided).
- AC-6 (no regression, stage 6). Build warning-clean (sm_86 or the arch of the machine; HIP paths in sync); `pytest -m "not slow"` as in AGENTS.md; `run_regression.py --suite full` against the merged-tree baseline (`develop` at the start of the task) and against upstream `master` 5c67f365 (VER-0037 B4: the non-deterministic set of 37 cases, plus the fork-only dftd2 cases and two dftd3 cases that differ by float rounding against upstream); models without flexible ZBL are bit-identical to the baseline binary; timing of universal-ZBL/no-ZBL qNEP within 3%; independent numerical-gpu and api-compat reviews without open BLOCKER/MAJOR.
- AC-7. `specs/traceability.yaml` updated; the guard test of R8 exists and fails when the restriction is re-inserted.
- AC-8 (outside the repository, by the requester). A v5.9.1-trained old-format flexible qNEP (`nep4_zbl_charge2 2 C F`, `zbl 0 0`), converted with `nep_model_converter.py`, gives the same one-step energy, forces, and virial in the patched fork and (as the old file) in v5.9.1 on 18 structures (no D3 and D3), within twice the same-version repeat difference and within energy 1e-3 meV/atom, force 1e-5 relative, virial 1e-5 relative. The check is repeated with the requester's production pair set (C-C 0.6/1.2, C-F 0.5/1.0, F-F 0.7/1.4 A, inner/outer) as well as the test set. No v5.9.1 reference exists for `charge_transfer` + flexible ZBL; AC-2 to AC-5 carry that case.
