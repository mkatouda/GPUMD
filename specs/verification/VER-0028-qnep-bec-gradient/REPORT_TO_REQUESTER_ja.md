## 1. 結論（要点）

1. **カーネルは「H0」の式のとおりに動いており、実装の誤りは見つかっていません。** 通常パス、small-box パスのどちらも同じです。学習側（`src/main_nep/`）も式は同じです（読解のみ。数値は未確認）。
   `BEC_k = s [ qn_k·1 + 0.5·T1_k + 0.5·T2_k ]`
   - s = sqrt(ε∞) = 0.98907（`nep.txt` のパラメータ index 6080）。
   - qn = q − mean(q)（`zero_total_charge` による中性化後の電荷）。
   - T1_k = Σ_j rel_jk ⊗ ∂q_k/∂r_j、T2_k = Σ_a rel_ak ⊗ ∂q_a/∂r_k。rel は MIC の相対ベクトル。
   - **T1、T2 の中の q は中性化前の「生の電荷」。** 中性化の連鎖則項は力側（`zero_mean_D_real`）にだけあり、BEC には入っていません。
2. **依頼書 2.2 の「オリゴマーでは (0.5, 0.5) が合わない」は、解析上の取り違えが原因でした。** 依頼元の `bec_code_formula.py` は、中性化後の電荷のヤコビアン Jn = J − S/N（S_k = Σ_a ∂q_a/∂r_k）を使っています。Jn は全ペアが非ゼロの非局所量で、40 Å セル中の 33 Å 分子では項 −(r_c − r_k)⊗S_k が大きくなります（RMS 0.43 e）。248 原子では 0.03 e で、小さい。生のヤコビアン J で当てはめると、**両構造とも a = b = 0.500**（残差 1.1e-3 / 2.1e-3 e）です。
3. **電荷中性化の項が BEC に欠けているのではありません（仮説 H1 は棄却）。** H1 との RMS 差は 0.431 e（オリゴマー）/ 0.029 e（アモルファス）。H0 との RMS 差は 3e-4（オリゴマー）/ 5e-4 e（アモルファス）（δ = 0.02 Å）で、δ を小さくすると 1/δ で増える float ノイズです。
4. **現行の BEC は、P の勾配ではありません（依頼書の症状の核心は正しい）。** 現行カーネルは並進不変（Σ_k Z_k = 0）ですが、ペアの重みが 0.5/0.5 の対称形で、かつ S_k ≠ 0 です（モデルは総電荷を局所的に保存しない。RMS|S| = 0.14–0.16 e/Å）。局所な BEC が単一値・並進不変な P の勾配になるための必要条件は、S_k = 0 です。

つまり、依頼書で「厳密」としていた Z_k（C3）は、比較の基準として不適切でした。数値表は次のとおりです（単位 e、s 倍込み、各列はオリゴマー / アモルファス）。

| 候補 | カーネルとの RMS | max |Σ_k Z_k| | 評価 |
|---|---|---|---|
| カーネル（0.5·T1 + 0.5·T2） | 0 / 0 | 0 / 0 | 並進不変だが勾配ではない |
| C1: qn·1 + T2（生の J、局所 MIC、基準点 k） | 0.122 / 0.186 | 8.9 / 14.4 | S_k ≠ 0 のため並進不変が壊れる |
| C3: qn·1 + T2（Jn、MIC）= 依頼書の「厳密」 | 0.425 / 0.188 | 0.95 / 13.9 | 非局所項が MIC で折り返される |
| C4: qn·1 + T2（Jn、プレーン差）= ∇(Σ qn·r) | 0.648 / 0.905 | 0.011 / 0.12 | 並進不変だが、アンラップ座標（重心）依存で周期境界では多価 |

## 2. 人間の決定（D1）と GPUMD 側の今後

人間が **D1 = (a)** を決めました。目標は次のとおりです。

- 生の電荷が総電荷を局所的に保存する（S_k = 0 を構成上保証する）モデルにする。
- 局所な Z_k = q_k·1 + Σ_a (r_a − r_k)_MIC ⊗ ∂q_a/∂r_k を、単一値・並進不変な P の厳密な勾配にする。
- これは**モデル構造の変更（再学習を伴う）**で、カーネル係数の変更だけではありません。
- S_k = 0 でも、現行の 0.5/0.5 の重みは勾配になりません（C1 と 0.12–0.19 e 違う）。新モデル用に BEC カーネルを T2 形（基準点 k）に変える必要があります。これは段階 2 で FD により確認します。

GPUMD 側の次の作業:
- DES-0005（電荷保存の構成法、`nep.txt` の形式、学習側と gpumd 側のカーネル）と ADR-0006（既存モデルの BEC を変えないこと）を作成し、人間の承認を得る。
- その後に実装（段階 2 以降）。実装、`nep` での学習、再学習（A6）は、承認後です。
- 構成法の候補は、対ごとの反対称な電荷移動 q_a = Σ_b t_ab（t_ab = −t_ba）などで、DES-0005 で比較します。現時点で決定していません。

DR-005 の草案と VER-0028 は、GPUMD リポジトリ（`develop`、未コミットの作業ツリー）にあります。

## 3. あなた（GPUMD-polymer-apps 側）へのお願い

GPUMD 側の実装を待たずに進められるものです。いずれも本リポジトリのスクリプトと解析の範囲で、GPUMD は触りません。

1. **スクリプトの訂正**: `bec_code_formula.py`、`bec_formula_fit.py`、README §4.3・4.5・§7 の「厳密な勾配（Jn ベース）」「オリゴマーで (0.5, 0.5) が合わない」を、本報告に合わせて訂正してください。生の電荷のヤコビアン J を得る方法は、VER-0028 README の「Method」と `scripts/bec_hypotheses.py`（`zero_total_charge` の起動だけを無効化した scratch ビルドを使用）を参照してください。
2. **疑似散逸の仮説の再評価**: 「BEC が勾配でない → 保存力にならない → 周期電場で正味の仕事」は、BEC が勾配でないことは確認できましたが、**それが疑似散逸の原因かは未検証**です。次の切り分けを提案します。
   - ゼロ電場で P = ∫ΣBEC·v dt が増え続ける原因が、(i) 非勾配性か、(ii) 周期系の MIC/ラップの扱いか、を分けてください。例えば、真空オリゴマー（`pq_vs_bec.py`）で ⟨ΔP²⟩ が 5 ps まで増え続けた 1.07 e²Å² が、BEC − 勾配（C1 や C4）の寄与でどこまで説明できるか。
   - 結晶の ⟨ΔP²⟩ が増え続ける問題は、BEC と v の積分の統計（相関時間）の確認も必要です。
3. **入力の提供**: 結晶 702 原子の `model.xyz`、N20 などの他モデルの `nep.txt` の場所、再学習用データセット（DFPT の BEC を含む）の場所と held-out 20 構造の指定を教えてください。A1・A6 に必要です。
4. **精度劣化の許容範囲**: S_k = 0 の制約付きモデルでは、BEC RMSE が現行（全成分 0.073 ± 0.012 e、対角 0.098 e）から悪化する可能性があります（前提 2）。「2 倍超なら人間が判断」としていますが、あなた側で許容できる値の目安があれば知らせてください。
