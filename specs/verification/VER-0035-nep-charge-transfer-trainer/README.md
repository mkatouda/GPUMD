# VER-0035: charge_transfer qNEP in the NEP trainer (DR-005 stage 3a)

- Status: implemented and verified 2026-11-11 (RTX A6000, sm_86, CUDA from /usr/local/cuda; float kernels, double accumulation of the ct sums). Type: regression (base binary vs candidate), cross-code consistency (`nep` vs gpumd, A4), mutation checks, training smoke test. Synthetic data only (VER-0032 generator weights/structures, random or teacher-generated labels). Not validation. No file of GPUMD-polymer-apps was used. `main_replica` untouched (stage 3b).
- Requirement DR-005; design DES-0005 sections 2-6; ADR-0006; kernels VER-0032 (charge/BEC) and VER-0034 (Dt, pair force/virial); formulas VER-0033.

## Implementation (src/main_nep, src/utilities/nep_io)
- Keyword `charge_transfer <rc_phi>` (exactly one number, 0 < rc_phi <= 100; given once). Errors: rc_phi > radial cutoff, charge_mode 1, `fine_tune`, USE_CJ build, `model nep/nep_dipole/nep_polarizability/nep_temperature/nep_vdw/nep_spin` ("charge_transfer is not supported by this model"), `qnep3_vdw` ("cannot be combined with charge_vdw"). Without the keyword nothing changes.
- Parameter vector: `number_of_variables += pairs * (basis_size_radial + 1)` (pairs = nt (nt + 1) / 2, upper triangle row-major); the phi block is the TAIL of the vector (after the descriptor coefficients). Initial values: uniform [0, 0.1] drawn from the same rng AFTER all other variables (the other variables keep their random numbers); no range limit. Regularisation: the phi variables belong to the group (type) of the first type of their pair (like the descriptor coefficients), so they enter the per-type and the total L1/L2 terms of `Fitness::regularize` like the other weights; SNES updates them like any other variable. `nep.restart` holds them (count check includes them).
- nep.txt (new format, written by `nep`, read by `nep` prediction and, converted, by gpumd): header field `charge_transfer rc_phi` and an extra block `@ phi_parameters N` after `@ q_scaler`; the legacy text that gpumd sees (`NEP_Model_File::get_md_input`) has the `charge_transfer` line immediately after `cutoff` and the phi values at the very end (VER-0032 layout). A file without the field/block is read exactly as before. Species compaction (`active`) handles the phi block (pair sub-selection). The nep.in value must agree with the nep.txt value in prediction mode (checked like the other settings).
- Kernels `src/main_nep/nep_charge/nep_charge_transfer.cuh`: a port of the gpumd header with the same arithmetic (shared header impossible: `NEP_Charge::ParaMB/ANN` are different types in `force/` and `main_nep/`; the trainer neighbour lists have a different layout, compact index and stored r12). Used only when `paramb.charge_transfer`; generic path only (no compiled/specialised kernels for these models). Flow in `find_force`: descriptors, ANN (h = charge output) -> copy h -> `ct_find_charge` writes q to `charge` and `charge_shifted` and V -> BEC (`ct_find_bec_B` + radial/angular Term A, then `scale_bec`; the 0.5/0.5 kernels and `find_bec_diagonal` do not run) -> long range with q (structure factor, `find_force_charge_long_range`, real-space for mode 1 n/a, self energy for mode 3: all unchanged) -> `ct_find_Dt_and_pair_force` (Dt, explicit pair force/virial) -> the unchanged descriptor force kernels with Dt as weight.
- Neutralisation in the trainer today (found by reading): (1) `enforce_nep_total_charge` (`zero_total_charge`): q_shifted = q + (charge_ref - sum q)/N per structure with the `charge=` label of the file (default 0); (2) `subtract_nep_charge_derivative_mean` (`zero_mean_D_real_train`): D -= mean D. Neither runs for charge_transfer models. The dataset reader does not neutralise anything (it only stores `charge=`), so DES-0005 does not conflict with the trainer structure (no SPEC_CONFLICT). Consequences to note: the charge loss `(sum charge - charge_ref)/Na` uses the array `charge` (raw network output in old models); for ct models `charge` holds q, so the charge loss is |charge_ref|/Na (zero for neutral labels; a non-zero `charge=` label cannot be represented by a ct model); `charge_*.out` of `nep` shows q (what gpumd dumps).

## Gate 3a-4: training smoke test (`scripts/ct_train_smoke.py`, `tests_pytest/test_nep_charge_transfer_train.py`)
Teacher: random model (seed 3) labelling six thin periodic structures (10 and 12 atoms; energy, virial, forces, BEC from the teacher's `nep` prediction). Student: `charge_transfer 4`, population 30, `output_interval 1`, seed 1; 537 parameters (522 + 15 phi).
- Note on loss.out: generation 1 of every model only runs `prepare_training` (q_scaler) and prints the regularisation alone (0.017 here), so "first generation" below is the first evaluated generation (row 2). This is existing behaviour of all models.
- 30 generations: loss 21.64 (gen 2) -> 9.91 (gen 30, also the minimum); 100 generations: 21.64 -> 7.72 (minimum = last). Decrease and best <= first: yes.
- Written nep.txt: fields `charge_transfer 4`, blocks `@ parameters 522`, `@ q_scaler 16`, `@ phi_parameters 15`. `nep` prediction on it: force RMSE 3.41079 vs loss.out 3.41079 (30 gen: 5.47387 vs 5.47387); gpumd reads the file and agrees (A4 table, last row).

It is NOT equal to the previous best because SNES samples the population as mu + sigma * N(0,1) and does not evaluate mu itself, so the best of 30 samples is a few percent away; the requested equality "within float noise" is therefore not measurable with the SNES output (stated here, not tuned).
- pytest (`tests_pytest/test_nep_charge_transfer_train.py`, 13 tests, 9 s): A4 for qnep2, qnep3 (rc_phi 4, 3; 2 and 3 types), 5 keyword error messages, 4 combination errors, the smoke test (gates: best <= first, last < first, A4 on the trained nep.txt, prediction force RMSE = loss.out to 1e-3 relative, restart first < 0.75 x fresh-start loss and <= 1.25 x previous last).

## Not verified / limits
Structures with more than 59 atoms and non-cubic cells in `nep` (the trainer's neighbour construction for triclinic thin cells is existing code); float vs double; `gpumd` compaction (`active`) of a charge_transfer nep.txt (phi sub-selection implemented, not run); `main_replica` (stage 3b); training on realistic data/convergence quality (A6); the old 0.5/0.5 trainer BEC is untouched for old models; fine_tune with charge_transfer is rejected; the loss for non-zero total-charge labels is not meaningful for ct models (now an input error, see follow-up item 1); the doc/ pages come in stage 4.

## Review follow-up (2026-11-11, items 1-10; all gates met; the only per-case gate is the trained-model force gate in item 7)
1. Non-zero `charge=` label (|charge| > 1e-6) with `charge_transfer` is an input error ("charge_transfer models are neutral by construction, but a structure has a non-zero charge= label", raised in `NEP_Charge_Reader::read_structure`); `charge=0` is accepted (pytest).
2. `charge_transfer` value: parsed as double, rejected if not finite, <= 0, `float(rc_phi) <= 0` (1e-50), or > 100 (pytest: 0, -1, 1e-50, nan, inf, -inf, abc, 4.5 > cutoff, repeated keyword, 2 values, none).
3. (a) `charge_transfer` with `model nep/nep_vdw/nep_dipole`, `model_type 1`, or `charge_mode 1`: "charge_transfer requires charge_mode 2 or 3 (qnep2/qnep3)." (`qnep3_vdw`: "cannot be combined with charge_vdw (qnep3_vdw)."). (b) `gpumd_replica`: "charge_transfer is not supported by gpumd_replica." (test_qnep_charge_transfer_field updated).
4. Writer order: nep.txt writes parameters, q_scaler, phi_parameters(, zbl_parameters); the MD converter emits parameters, q_scaler, zbl, phi. Flexible ZBL exists only for model nep and charge_transfer only for qnep2/qnep3, so they never coexist; comments in both writers, and `get_md_input` now refuses the combination ("charge_transfer cannot be combined with flexible ZBL parameters"), so the order cannot diverge silently.
5. Compaction (gpumd species subset) works. New-format files: `NEP_Model_File::read_and_compact` selects the phi pairs (`triangular_pair_index`). Legacy text files: `compact_nep.cu` did NOT know the `charge_transfer` line (it would have read it as `n_max`); fixed (line copied after cutoff, phi block compacted with the same pair rule). Test (`scripts/ct_compact_check.py`, pytest): 3-type model (Na Cl Mg) on a Na/Cl-only structure (compaction active) vs the 2-type model selected by numpy from the same arrays (independent oracle), n45 L14: new format max |dE|, |dq|, |dF|, |dBEC| = 0 (bit-identical); legacy file 4.9e-8, 3.2e-8, 6.0e-7, 1.2e-7 (float rounding of the decimal text; RMS BEC 0.18, RMS F 0.54); pytest gates 1e-6 (new) and 1e-5 (legacy).
6. Build dependency: `HEADERS` in the makefile globs `main_nep/*/*.cuh`; `make -n nep` after `touch nep_charge_transfer.cuh` lists `main_nep/nep_charge/nep_charge.o` (and every other object): rebuilt, no change needed. clang-format was re-run on changed lines (the include re-ordering it proposes in files where one include line was added was not applied).
7. Tighter A4 gates in pytest: BEC 5e-6 e, force 1e-5 eV/A, energy 1e-5 eV/atom (charge 1e-5). Worst measured cases pass: 3 types, rc_phi 4, structures 1,4: BEC 7.8e-7, force 7.2e-6, dE 1.6e-6 (virial/atom 1.8e-5, not gated); 3 types rc_phi 3: 3.7e-7, 1.7e-6, 3.6e-7. The trained-model case (|F| RMS 26 eV/A from random teacher data) keeps force gate 1e-4 (measured 1.4e-5, relative 5e-7; float noise scales with |F|); its BEC (1.5e-6) and energy (1.9e-6) use the tight gates. New small mutations (A4 on qnep2, 4 structures): dphi x 1.001 -> BEC 1.9e-4, force 5.7e-4, virial/atom 4.3e-4: caught; Dt x 1.001 -> force 4.8e-4, virial/atom 2.8e-4: caught; V (Term A weight) x 1.001 -> BEC 1.8e-4: caught. (The earlier large mutations Term A, Term B, Dt = 0, pair term dropped are also caught.) All mutations restored (`diff` against the saved header) and the binaries rebuilt.
8. Independent oracle (`scripts/ct_fd_trainer.py`, pytest): the trainer's forces/virial in `nep` prediction mode against central FD of the trainer's own energy (delta 0.005 A, 12 atoms; strain 0.005, six components; one train.xyz per run), CT vs the same weights without charge_transfer ("old floor"):

## Decision of the human (2026-11-11): force gate of the trained model
The trained-model A4 force gate is relative: RMS(dF) <= 1e-6 x RMS(F) (RMS F = 26 eV/A, measured dF 1.4e-5 eV/A, i.e. ~5e-7 relative). It replaces the absolute 1e-4 used by the implementer (float noise scales with |F|). All other A4 gates are unchanged (BEC 5e-6 e, force 1e-5 eV/A, energy 1e-5 eV/atom).
