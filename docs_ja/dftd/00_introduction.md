# 第0章 はじめに

## 0.1 この機能は何か

GPUMD の NEP（ニューラルエボリューションポテンシャル）に、**外付けの分散力（van der Waals）補正**を加える機能です。次の二つのキーワードがあります。

| キーワード | 補正の種類 | 概要 |
|---|---|---|
| `dftd3` | DFT-D3（Becke-Johnson ダンピング、二体項のみ） | 配位数に依存する C6 係数を使う。汎関数ごとのパラメータ表を内蔵 |
| `dftd2` | DFT-D2（Grimme 2006） | 元素ごとに固定の C6, R0 を使う単純な二体補正。s6 はユーザーが直接指定する |

どちらも、NEP の力・エネルギー・ビリアルを計算した直後に、原子ごとのエネルギー・力・ビリアルへ加算されます [01 章 1.6 節、コード: `nep.cu` の `compute()`]。そのため `thermo.out`、`dump_xyz`、ビリアルから求める圧力など、通常の出力にそのまま反映されます。

`dftd3` は upstream GPUMD に既にあるキーワードです。このフォークでは、結果を変えずに高速化しました（DR-001）。`dftd2` はフォークで新規に追加したキーワードです（DR-002）。upstream には `dftd2` がありません。

## 0.2 二重計上に関する最重要の注意

どちらの補正も「NEP が分散力を含んでいない」ことを前提にした**外付け補正**です。NEP の訓練データに既に分散力が含まれている場合は、補正を加えると分散力を二重に数えることになります [DR-002 本文、dftd2.rst Tips]。

- 訓練データを生成した第一原理計算が、分散力補正なしの GGA（例：PBE 単独）であれば、補正を加える意味があります。
- 訓練データが PBE-D3、PBE-D2、あるいは vdW-DF、rVV10 のような非局所汎関数で作られていた場合は、補正を加えないでください。
- 公開されている NEP モデルを使う場合は、訓練データの作成条件（汎関数、分散力補正の有無）を必ず確認してください。
- `dftd3` の第1引数（汎関数名）は、**NEP の訓練データを作った汎関数**に合わせます [dftd3.rst Syntax]。
- `nep_vdw` / `qnep3_vdw` は独自の vdW 項を持ちます。そこへ `dftd2` を加えると二重計上になり得ます。ユーザーの責任です [dftd2.rst Tips]。`dftd3` はこれらのモデルでは使えません（01 章参照）。

## 0.3 D3 と D2 のどちらを使うか

以下は使い分けの**指針**であり、測定で示された結果ではありません。

| 観点 | D3（`dftd3`） | D2（`dftd2`） |
|---|---|---|
| 推奨度 | 通常はこちらを推奨 | 単純な補正が欲しい場合、比較用 |
| 理由 | 配位数に依存する C6 を使うため、原子の化学環境の違いを（D2 より）反映できる。汎関数ごとの BJ パラメータ表を内蔵している | 元素ごとの固定 C6 とユーザー指定の s6 だけで動作が単純。他の D2 実装との比較に使える |
| パラメータ | 汎関数名で決まる（s6, s8, a1, a2） | s6 のみ（PBE では 0.75 が Grimme の値だが、値の選択はユーザーの責任） [dftd2.rst Limitations] |
| 元素 | H から Pu（94 元素）[コード: `NUM_ELEMENTS=94`] | H から Rn（Z ≤ 86）。Z > 86 の元素が構造にあるとエラー [DR-002 D5] |
| 対応ポテンシャル | NEP 系（`nep4*`、`nep4_charge*` 系）。`nep_vdw`/`qnep3_vdw` は不可 | 上に加え `nep_vdw`/`qnep3_vdw` も可 |
| カットオフ | 2 個（ポテンシャル用、配位数用）をユーザーが指定。典型例は 12 Å と 6 Å | 1 個。省略時は 30 Å（既定値）。コストは大きなカットオフでかなり増える |
| 打ち切り | 打ち切り位置で滑らかにする処理は無い（コード読解のみ。打ち切り誤差の大きさは記録に無い） | シフト付き力（shifted-force）で、エネルギーと力が打ち切り位置で連続的にゼロになる [DR-002 D1] |
| 金属・イオン性 | 配位数依存性は含まれるが、二体項のみ（ATM 三体項なし） | 中性原子の固定 C6 のため、イオン性・金属系は過剰結合になり得る [dftd2.rst Limitations] |

どちらも二体項のみで、三体項（Axilrod-Teller-Muto）はありません [VER-0001, dftd2.rst Limitations]。どちらの結果も DFT や実験に対して**検証（validation）されたものではありません**。06 章を参照してください。

D2 の既定カットオフ 30 Å は、軽元素（水、グラファイト、MgO）での収束テストに基づいており、重元素・高密度系では収束していません（fcc Au では 30 Å で、打ち切りなしの和に対し 10.1 meV/原子のずれ）[dftd2.rst, VER-0007 s3]。このような系では、カットオフの収束確認が必要です（1 章参照）。

## 0.4 動作環境

| 項目 | 内容 |
|---|---|
| 必要なもの | NVIDIA GPU と CUDA（`nvcc`）。`src/` で `make` して `gpumd` を作ります [AGENTS.md Build] |
| 開発・検証環境 | RTX A6000（sm_86）、CUDA 12.3 [VER-0018] |
| 他の GPU | 動作・性能とも未測定。D3/D2 の並列化パラメータ（スレッド数の選び方など）は RTX A6000 で調整した値です [VER-0004, VER-0008] |
| HIP（AMD） | `gpu_macro.cuh` 経由で書いてあるが、ビルド・動作とも**未検証** [DR-001 AC-5 注記] |
| 複数 GPU 版 NEP | `dftd3` / `dftd2` とも非対応（エラー）[コード: `nep_multigpu.cu`] |
| `gpumd_replica` | `dftd2` を実装していない（キーワードを読まず、補正も適用されない）[dftd2.rst]。`dftd3` についても `src/main_replica` にコードは無い（コード読解のみ、挙動は未実行） |
| 入力ファイル | 通常の `run.in` と `model.xyz`。補正は `run.in` の 1 行を加えるだけです |

## 0.5 このマニュアルの読み方

1. 初めて使う方は 01 章の「入力例」から始め、`examples/gpumd_dftd3` または `examples/gpumd_dftd2` を**作業用ディレクトリにコピーして**実行してください。
2. 補正の有無による差だけを取り出す方法も 01 章に記載しています。
3. カットオフの決め方と計算コストの見積もりは、01 章の方針と 03 章の測定表を併せて読んでください。
4. 結果の信頼性（何が検証され、何が未検証か）は 06 章にまとめています。特に「未測定の一覧」と「既知の制限」を確認してください。
5. 理論式、ソース構成、実装技法は、02・04・05 章と付録（A1〜A3）にあります。

## 0.6 検証の種類について（用語）

本マニュアルでは次の三つを区別します（詳細は 06 章）。

- **検証（verification）**：解析解や独立実装との一致、有限差分との整合性など、「式が正しく実装されているか」の確認。
- **回帰（regression）**：変更前後のバイナリの出力比較。「前と同じか」の確認であり、物理的な正しさの保証ではありません。
- **妥当性確認（validation）**：DFT 計算や実験との比較。**このマニュアルが依拠する記録には、これに該当するものはありません** [各 VER ヘッダ]。
