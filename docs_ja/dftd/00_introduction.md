# 第0章 はじめに

## 0.1 この機能は何か

GPUMD の NEP（ニューラルエボリューションポテンシャル）に、**外付けの分散力（van der Waals）補正**を加える機能です。次の二つのキーワードがあり、それぞれに複数の形式があります。

| キーワード | 形式 | 補正の種類 | 概要 |
|---|---|---|---|
| `dftd3` | 既定（`bj`） | DFT-D3（Becke-Johnson ダンピング、二体項のみ） | 配位数に依存する C6 係数を使う。汎関数ごとのパラメータ表を内蔵 |
| `dftd3 ... zero` | `zero` | DFT-D3(0)（ゼロダンピング、二体項のみ）[DR-003] | 同じ C6・C8 に、ゼロダンピング関数 f_n を使う。汎関数ごとの表は BJ とは別（dftd3-lib の表から生成）。Z ≤ 86 のみ |
| `dftd2` | 既定（`table grimme2006 trunc sf`） | DFT-D2（Grimme 2006） | 元素ごとに固定の C6, R0 を使う単純な二体補正。s6 はユーザーが直接指定する |
| `dftd2 ... table qe` | `table qe`（`trunc` は `sf` か `plain`）[DR-004] | Quantum ESPRESSO 7.2 の `dftd3_version = 2` と同じパラメータの D2 形式 | 「D2 の式に D3 の表を使うもの」（C6 は D3 の最初の参照点、R0 = 1.1 × D3 の `r0ab`）。Grimme 2006 の D2 **ではない**。Z ≤ 86 のみ |

どちらも、NEP の力・エネルギー・ビリアルを計算した直後に、原子ごとのエネルギー・力・ビリアルへ加算されます [01 章 1.6 節、コード: `src/force/nep/nep.cu` の `compute()`]。そのため `thermo.out`、`dump_xyz`、ビリアルから求める圧力など、通常の出力にそのまま反映されます。

`dftd3` は upstream GPUMD に既にあるキーワードです。このフォークでは、結果を変えずに高速化しました（DR-001）。`dftd3 ... zero` の追加（DR-003）は、キーワードの末尾に任意のトークンを 1 つ足すだけで、トークンを省略した入力と `bj` を明示した入力は従来のバイナリとビット単位で同一の結果を与えます [DR-003 AC-3, VER-0024 6 節]。`dftd2` はフォークで新規に追加したキーワードです（DR-002）。upstream には `dftd2` がありません。`table` と `trunc` の追加（DR-004）でも、オプションなしの入力は従来と同じ画面出力を保ちます。ただし DR-004 の R3（高速化、ADR-0005）により、`dftd2` の全入力で結果の下位の桁が従来のバイナリと変わります（許容値は DR-002 AC-1 の範囲内。06 章 6.11 節）。

## 0.2 二重計上に関する最重要の注意

どちらの補正も「NEP が分散力を含んでいない」ことを前提にした**外付け補正**です。NEP の訓練データに既に分散力が含まれている場合は、補正を加えると分散力を二重に数えることになります [DR-002 本文、dftd2.rst Tips]。

- 訓練データを生成した第一原理計算が、分散力補正なしの GGA（例：PBE 単独）であれば、補正を加える意味があります。
- 訓練データが PBE-D3、PBE-D2、あるいは vdW-DF、rVV10 のような非局所汎関数で作られていた場合は、補正を加えないでください。
- 公開されている NEP モデルを使う場合は、訓練データの作成条件（汎関数、分散力補正の有無）を必ず確認してください。
- `dftd3` の第1引数（汎関数名）は、**NEP の訓練データを作った汎関数**に合わせます [dftd3.rst Syntax]。
- 逆向きの使い方もあります。訓練データのラベルから**あらかじめ分散力を引いて**（例えば QE の D3(0) や `dftd3_version = 2` の D2 を差し引いて）NEP を訓練した場合は、MD で同じ補正を**足し戻す**必要があります。この場合は、ラベルを作ったときの補正の種類（ダンピング、テーブル、打ち切り、カットオフ）と MD の設定を一致させます（下流の用途：D3(0) または QE 型 D2 を、分散力を引いたラベルで訓練した NEP へ足し戻す [DR-003 Downstream need, DR-004 Origin]）。一致の度合い（QE との整合、三体項の有無など）は 06 章 6.10・6.11 節にあります。
- `nep_vdw` / `qnep3_vdw` は独自の vdW 項を持ちます。そこへ `dftd2` を加えると二重計上になり得ます。ユーザーの責任です [dftd2.rst Tips]。`dftd3` はこれらのモデルでは使えません（01 章参照）。

## 0.3 D3 と D2 のどちらを使うか

以下は使い分けの**指針**であり、測定で示された結果ではありません。

| 観点 | D3（`dftd3`） | D2（`dftd2`） |
|---|---|---|
| 推奨度 | 通常はこちらを推奨（`bj` と `zero` の選び方は 0.3.1 節） | 単純な補正が欲しい場合、比較用 |
| 理由 | 配位数に依存する C6 を使うため、原子の化学環境の違いを（D2 より）反映できる。汎関数ごとの BJ パラメータ表を内蔵している | 元素ごとの固定 C6 とユーザー指定の s6 だけで動作が単純。他の D2 実装との比較に使える |
| パラメータ | 汎関数名で決まる（s6, s8, a1, a2） | s6 のみ（PBE では 0.75 が Grimme の値だが、値の選択はユーザーの責任） [dftd2.rst Limitations] |
| 元素 | BJ：H から Pu（94 元素）[コード: `NUM_ELEMENTS=94`]。`zero`：H から Rn（Z ≤ 86）。Z ≥ 87 があるとエラー [DR-003 D5] | H から Rn（Z ≤ 86）。Z > 86 の元素が構造にあるとエラー [DR-002 D5]。`table qe` も Z ≤ 86 [DR-004 P3] |
| 対応ポテンシャル | NEP 系（`nep4*`、`nep4_charge*` 系）。`nep_vdw`/`qnep3_vdw` は不可 | 上に加え `nep_vdw`/`qnep3_vdw` も可 |
| カットオフ | 2 個（ポテンシャル用、配位数用）をユーザーが指定。典型例は 12 Å と 6 Å | 1 個。省略時は 30 Å（既定値）。コストは大きなカットオフでかなり増える |
| 打ち切り | 打ち切り位置で滑らかにする処理は無い（コード読解のみ。打ち切り誤差の大きさは記録に無い） | 既定はシフト付き力（shifted-force）で、エネルギーと力が打ち切り位置で連続的にゼロになる [DR-002 D1]。`trunc plain` ではシフトなしの単純打ち切り（段差あり。01 章） |
| 金属・イオン性 | 配位数依存性は含まれるが、二体項のみ（ATM 三体項なし） | 中性原子の固定 C6 のため、イオン性・金属系は過剰結合になり得る [dftd2.rst Limitations] |

### 0.3.1 ダンピングとテーブルの選び方（BJ とゼロ、Grimme 2006 と QE 型）

以下も指針です。第一の基準は「NEP の訓練データのラベル（または比較対象の第一原理計算）がどの形式の補正を使ったか」です。

| 状況 | 選ぶ形式 | 理由と注意 |
|---|---|---|
| ラベルの汎関数が BJ ダンピングの D3 を想定している、または特に指定がない | `dftd3 <汎関数> <rc> <rc_cn>`（既定の `bj`） | 従来の挙動。汎関数ごとの BJ パラメータ（`pbe` など）を内蔵 |
| 第一原理側が D3(0)（ゼロダンピング。QE の `dftd3_version = 3`、simple-dftd3 の zero damping など）を使った | `dftd3 <汎関数> <rc> <rc_cn> zero` | 汎関数名は BJ と同じ綴り（`pbe`、`revpbe`、`blyp`、`b3lyp`、`tpss` など）。ゼロダンピングの表に無い汎関数はエラー（BJ にフォールバックしない）。Z ≤ 86。**三体項は無い**ため、三体項を有効にした QE の既定（`dftd3_threebody = .true.`）とは三体項の分だけ異なる [DR-003 範囲外] |
| 第一原理側が QE の `dftd3_version = 2` を使った（INPUT_PW は「Original Grimme-D2」と説明するが実際は異なる） | `dftd2 <s6> <rc> table qe [trunc plain]`（`rc` は明示必須） | C6 と R0 の出典が Grimme 2006 ではなく D3 の表。QE と同じハードカットオフは `trunc plain`。Z ≤ 86 [DR-004 D3, VER-0025 2 節] |
| 元素ごとに固定の C6, R0 の単純な D2（Grimme 2006）で十分、または他の D2 実装との比較 | `dftd2 <s6> [<rc>]`（既定） | シフト付き力の打ち切りで、既定は 30 Å |

- 「Grimme 2006 の D2」と「QE 型の D2（D2 の形式に D3 の表）」は**別の補正**で、同じ `s6` でもエネルギーは異なります。ラベルを作った補正に合わせ、ラベル生成と MD で**テーブルと打ち切りの設定を記録して一致させる**ことを推奨します [DR-004 AC-8]。
- `table qe` と `trunc plain` は、カットオフを明示しないとエラーです（ラベルのカットオフと一致させるため。既定の 30 Å は別の目的の値） [ADR-0004 項目 6]。
- ゼロダンピングとの間に、BJ との間のような「どちらが良い」という測定はありません。どちらのダンピングも、DFT や実験に対して検証（validation）していません（0.6 節）。

どちらも二体項のみで、三体項（Axilrod-Teller-Muto）はありません [VER-0001, dftd2.rst Limitations]。どちらの結果も DFT や実験に対して**検証（validation）されたものではありません**。06 章を参照してください。

D2 の既定カットオフ 30 Å は、軽元素（水、グラファイト、MgO）での収束テストに基づいており、重元素・高密度系では収束していません（fcc Au では 30 Å で、打ち切りなしの和に対し 10.1 meV/原子のずれ）[dftd2.rst, VER-0007 s3]。このような系では、カットオフの収束確認が必要です（1 章参照）。

## 0.5 このマニュアルの読み方

1. 初めて使う方は 01 章の「入力例」から始め、`examples/gpumd_dftd3`（ゼロダンピングの例を含む）または `examples/gpumd_dftd2` を**作業用ディレクトリにコピーして**実行してください。
2. 補正の有無による差だけを取り出す方法も 01 章に記載しています。
3. カットオフの決め方と計算コストの見積もりは、01 章の方針と 03 章の測定表を併せて読んでください。
4. 結果の信頼性（何が検証され、何が未検証か）は 06 章にまとめています。特に「未測定の一覧」と「既知の制限」を確認してください。D3(0) は 6.10 節、QE 型 D2 は 6.11 節です。
5. 理論式、ソース構成、実装技法は、02・04・05 章と付録（A1〜A3）にあります。

## 0.6 検証の種類について（用語）

本マニュアルでは次の三つを区別します（詳細は 06 章）。

- **検証（verification）**：解析解や独立実装との一致、有限差分との整合性など、「式が正しく実装されているか」の確認。
- **回帰（regression）**：変更前後のバイナリの出力比較。「前と同じか」の確認であり、物理的な正しさの保証ではありません。
- **妥当性確認（validation）**：DFT 計算や実験との比較。**このマニュアルが依拠する記録には、これに該当するものはありません** [各 VER ヘッダ]。
