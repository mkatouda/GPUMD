本章は、D3/D2 の GPU 実装で採用した技法と、検討して採用しなかった案を、開発者向けに説明します。ファイル構成とカーネルの一覧は 04 章、理論式は 02 章、検証結果は 06 章にあります。

**対象のリビジョン**：`develop` `90bff065`（upstream/master `aa63ffdd` をマージした後）。本章の行番号はすべてこのリビジョンのものです（ソースを変更すると行番号はずれます）。DR-003（D3(0) ゼロダンピング）、DR-004（`dftd2` の `table qe`、`trunc plain`、R3 の補償付き float 累算）、upstream のサブフォルダ再構成（VER-0027）を反映しています。

出典の略記は 04 章と同じです（`D3:n` = `src/force/dftd3/dftd3.cu` の n 行目、`DZ:n` = `src/force/dftd3/dftd3zero_table.cuh`、`P3:n` = `src/force/dftd3/dftd3para.cuh`、`D2:n` = `src/force/dftd2.cu`、`QT:n` = `src/force/dftd2qe_table.cuh`）。性能の数値は、すべて RTX A6000（sm_86、84 SM）、CUDA 12.3、NEP89、`dftd3 pbe 12 6` での nsys 測定です [DES-0001、各 VER]。他の GPU や HIP では測定していません。「導出」「推論」とあるものは、記録やコードから本マニュアル作成者が導いたもので、実行して確認していません。

## 5.1 D3 の計算フロー

D3 の 1 ステップは、**配位数（CN）→ 力（ペア項）→ extra（CN 微分項）**の 3 段階です。小箱経路では、その前に近傍リストの構築が、大箱経路では、前にセルリストの構築が入ります（04 章 4.4 節の図）。

| 段階 | カーネル（小箱 / 大箱） | 入力 | 出力 |
|---|---|---|---|
| 1. CN | `find_dftd3_coordination_number_small_box` / `…_large_box` | 位置、`rc_cn` 内の近傍 | `cn`、`cn_weight`（5 個／原子）、（大箱のみ）CN リスト |
| 2. 力 | `add_dftd3_force_small_box` / `find_dftd3_force_large_box` | `cn`、`cn_weight`、`rc_pot` 内の近傍 | エネルギー、ペア項の力、ビリアル、`dc6_sum`、`dc8_sum` |
| 3. extra | `add_dftd3_force_extra_small_box` / `find_dftd3_force_extra_large_box` | `dc6_sum`、`dc8_sum`、`rc_cn` 内の近傍 | CN 微分による力とビリアル |

### 5.1.1 段階の間の依存

- 力カーネルは、ペアの両端の CN を必要とします（C6 が両原子の CN に依存するため）。したがって CN カーネルが全原子分を終えてから力カーネルを起動します。
- extra カーネルは、力カーネルが書く `dc6_sum`、`dc8_sum` を必要とします。したがって力カーネルの後です。

この依存のため、3 つのカーネルを 1 つに融合することはできません [VER-0015：extra は力カーネルの `dc6_sum`/`dc8_sum` を必要とし、力カーネルは両原子の CN を必要とする]。

### 5.1.2 extra が表すもの

D3 のエネルギーは、ペアの距離 r だけでなく、両原子の配位数 CN_i、CN_j（C6 を通じて）にも依存します。したがって力は、

- **ペア項**：r への明示的な依存の微分（力カーネルが計算）、
- **CN 項**：CN が r に依存することによる微分（extra カーネルが計算）

の和になります（式の導出は 02 章）。この CN 項が「extra」です。

コード上は次のようになっています。

1. 力カーネルは、ペアごとに `dc6`（C6 の CN 微分）を求め、原子ごとに合計を作ります（`D3:721-722`）。

```cpp
// D3:721-722（add_dftd3_force_small_box、ペアループ内。g6、g8 は d3_damped_pair の出力）
    dc6_sum += dc6 * dftd3_para.s6 * g6;
    dc8_sum += dc6 * c8_over_c6 * dftd3_para.s8 * g8;
```

2. extra カーネルは、`rc_cn` 内の各相手について CN 関数 `1/(1+exp(-16((Rcov_1+Rcov_2)/r − 1)))` の r 微分に対応する係数 `k12` を作り、`D = dc6_sum + dc8_sum` を掛けて力にします（`D3:833-838`）。原子 1 に作用する力は `k12·(D_1 + D_2)·r12` です。

```cpp
// D3:833-838（add_dftd3_force_extra_small_box）
    const float cn_exp_factor = exp(-16.0f * ((R_cov_1 + R_cov_2) / d12 - 1.0f));
    const float dc_sum_2 = g_dc6_sum[n2] + g_dc8_sum[n2];
    float k12 = cn_exp_factor * 16.0f * (R_cov_1 + R_cov_2); // not 8.0f
    k12 /= (cn_exp_factor + 1.0f) * (cn_exp_factor + 1.0f) * d12 * d12_2;
    const float f2 = k12 * (dc_sum_1 + dc_sum_2);
    const float f2_virial = k12 * dc_sum_2;
```

3. ビリアルへの配分は、相手の `D_j` だけを使います（`f2_virial`）。原子ごとのビリアルは非対称になりますが、全体の和は正しい、という設計です（`D3:779-781` のコメント、UPSTREAM-0002 G）。

**CN のカットオフは `rc_cn`、ペア項のカットオフは `rc_pot`** と別々です。そのため extra カーネルは、力カーネルとは別の近傍リスト（通常は `rc_cn` ≤ `rc_pot` なので、より短いもの）を使います。小箱では `NL_angular`、大箱では angular セルリストまたは CN リストです。

### 5.1.3 減衰ヘルパー `d3_damped_pair` と `d3_zero_term`（DR-003）

BJ とゼロダンピングの違いは、ペアごとの**減衰した二体項**だけです。この部分を、小箱の力カーネル（`D3:706`）と大箱の力カーネル（`D3:1233`）が共有するデバイス関数 `d3_damped_pair`（`D3:212-253`）に切り出しています。CN、C6 の補間、`dc6_sum` / `dc8_sum`、extra カーネル、縮約は、どちらの減衰でも同一のコードです。

| 項目 | 内容 |
|---|---|
| 入力 | `DFTD3_Para`（値渡し）、原子番号の添字 `z1`、`z2`、ペアの C6（eV Å⁶）、`c8_over_c6`、距離の 2 乗 `d12_2` |
| 出力 | `pe`（ペアのエネルギーの半分。完全リストなので各原子が半分ずつ受け取る）、`f2`（力 = `2·f2·r12`）、`g6`、`g8`（減衰した関数。エネルギーでは C6、C8 に `s6·g6`、`s8·g8` が掛かる。CN 微分用の `dc6_sum`、`dc8_sum` の計算に使う） |
| BJ の枝（`damping == 0`、`D3:225-239`） | 従来のコードと**演算の順序を変えていません**（DR-003 AC-3）。`g6 = damp_6`、`g8 = damp_8` を返すだけ |
| ゼロの枝（`damping == 1`、`D3:240-252`） | R0 を表から引き（下記）、`d3_zero_term<6>`、`d3_zero_term<8>` を呼ぶ |

パラメータ構造体 `DFTD3_Para`（`D3h:25-34`）は、減衰の種類 `damping`（0 = BJ、1 = ゼロ）、共通の `s6`、`s8`、BJ だけの `a1`、`a2`、ゼロだけの `sr6`、`sr8` を持ちます。ゼロダンピングの汎関数は `D3ZERO_PARAMS[48]`（`DZ:439-440`）から名前で選び（`DFTD3::initialize`、`D3:1935-1945`）、BJ の表とは別です。名前の綴りは BJ の表と同じ（`blyp`、`b3lyp` など。ADR-0003 項目 8）で、どちらかの減衰に無い汎関数は、減衰の名前を含むエラーになります（`D3:2003-2008`。フォールバックなし、ADR-0003 項目 3）。

**`d3_zero_term<n>`（`D3:172-205`）**：べき n（6 または 8）、α = n + 8（14 または 16）について、

```text
f(r) = 1 / (1 + 6 t^(-α)),   t = r / (sr_n · R0),   inv_a = 1 / (sr_n · R0)
g = f(r) / r^n,    h = n − α (1 − f),    dg/dr = −g·h / r
```

を返します（`g` が `g6`/`g8`、`h` が力の係数）。`t^(-α)` を素直に書くと、r が小さいとき `t^(-α)` が float の範囲を超えるので、2 つの形を使い分けます。

| 範囲 | 形 | 使う量 |
|---|---|---|
| `t < 1`（`D3:178-190`） | `g = t^8 · inv_a^n / (t^α + 6)`、`h = n − 6α/(t^α + 6)` | `t^α ≤ 1`（`t^14 = t^8·t^4·t^2`、`t^16 = t^8·t^8`。`n` はテンプレート引数なので、分岐はコンパイル時に決まる） |
| `t ≥ 1`（`D3:191-203`） | `g = r^(−n) / (1 + 6 q)`、`h = n − 6α q/(1 + 6 q)`、`q = t^(−α)` | `q ≤ 1`（`u = 1/t` の冪） |

どちらの形も、1 以下の数の冪と、それを含む和・商だけを使うので、**どの r でもオーバーフローしません**。`r → 0` では `g → 0` です（コードのコメント）。2 つの形は数学的に同じ式で、`t = 1` でつながります（導出。ビット単位の一致は主張しません）。

**r = 0 の保護（`D3:250-251`）**：`f2 = d12_2 > 0 ? 0.5·(s6·c6·g6·h6 + s8·c8·g8·h8) / d12_2 : 0`。重なった原子（r = 0）で `0/0` による NaN を出さず、力はちょうど 0 になります。ゼロダンピングの枝にだけある保護です（BJ の枝は変更しない）。極端な近距離で NaN / inf が出ないことは `test_extreme_short_distance_is_finite`（周期・非周期）が確認しています [VER-0024 2 節]。

**単位と定数**：R0 は**Å** で表に格納されます（`DZ:22-23` のコメント、値は float リテラル）。距離はデバイス側で float の `sqrt(d12_2)`（Å）なので、`t` は Å 同士の比です。BJ の `a2` は bohr の表の値に `Bohr` を掛けて Å にしています（`D3:1508`）。両方の減衰で `dftd3para.cuh` の `Bohr`（`0.5291772575069165f`）を使います（ADR-0003 項目 9）。参照実装の simple-dftd3 は CODATA 2018 を使うため、α = 14 の減衰の遷移領域で相対 1.5×10⁻⁶ までの差が出ますが、この差は許容値の BASELINE に**含まれています** [VER-0023 2 節、VER-0024 5 節]。dftd3-lib の float32 リテラルは使いません（厳しいオラクルにできないため、VER-0023 6 節）。

**R0 の表（`d3zero_r0ab`）**：`__constant__ float d3zero_r0ab[4465]`（`DZ:24`、17,860 B）。添字は `zl·(zl+1)/2 + zs`（0 始まりの原子番号 `zl ≥ zs`、`D3:242-244`）の下三角で、4465 = 94·95/2 です（Z = 1〜94 の分）。**使うのは Z ≤ 86 の分（3741 個）だけ**です。生成元は dftd3-lib（コミット `3c99ee98`）の `lib/core.f90`（ヘッダのコメント、VER-0023）。Z = 87〜94 は dftd3-lib（と QE）と simple-dftd3 で r0ab、C6 が異なり、どちらが正しいか決めていないため、D3(0) は Z ≤ 86 に限ります（DR-003 D5、06 章 6.10.1 節）。

**元素検査（`DFTD3::check_elements`、`D3:2058-2084`）**：`compute` の冒頭で、`damping == 1` かつ未検査のときだけ呼びます（`D3:1903-1905`）。`type` をホストへ複写し、構造に**実際にある**原子種について、NEP ファイルの 1 行目の元素記号から決めた添字（`atomic_number`）が 86 以上なら、元素名つきでエラーにします（`... D3(0) is limited to Z <= 86 (H-Rn); use bj damping or remove these elements.`）。`type` が要るので、`initialize` ではなく**最初の力の評価**で検査します。`elements_checked` は `initialize` で偽に戻ります（`D3:2033`）。BJ には適用しません（Z ≤ 94 まで使える。`test_bj_damping_still_accepts_z_above_86`）。NEP89 には Ac〜Pu が載っていますが、構造にある原子種だけを検査します。

### 5.1.4 ゼロダンピングの小箱の CN を倍精度にする理由と範囲（VER-0024）

**問題**：D3 のビリアルでは、CN の勾配項（extra カーネル）とペアのビリアル項が**ほぼ打ち消し合います**。倍精度の NumPy による診断（GPUMD の規約）で、graphite の xx 成分は −3.427 + 3.413 = −0.0142 で、項の絶対値の和／合計が最大 1331 でした。ここでは float の丸めが拡大されます。診断の結果、float の累算、ペア項の精度、C6 の補間は主因ではなく、**単精度の小箱 CN カーネル**が主因でした。BJ 用に暫定導出した許容値では、ビリアルだけが 20 ケース中 2 ケースで不合格でした（pbe:graphite 9.79×10⁻⁶ eV 対 8.96×10⁻⁶、pbe:heavy_cluster 2.05×10⁻⁶ 対 1.06×10⁻⁶。ADR-0002 の上限は変更せず）[VER-0024 1 節]。

**実装**：

| 項目 | 内容 |
|---|---|
| `cn_sum_small_box<T>`（`D3:256-281`） | 近傍リスト `NL_angular` 上の CN の和。`T = float`（BJ）または `T = double`（ゼロダンピング）。`R_cov`、`exp`、和を `T` で行う。リストの変位 `r12` は float を読み、`(T)Bohr` は float の定数 `Bohr` を `T` に変換して使う（`D3:269`） |
| `find_dftd3_coordination_number_small_box`（`D3:283-310`） | `dftd3_para.damping == 0` なら `cn_sum_small_box<float>`、それ以外は `<double>`（`D3:298-308`）。ゼロダンピングでは `g_cn[n1]` を float に丸めて保存する（`D3:306`） |
| `store_cn_weights<T>`（`D3:62-75`） | `diff = cn − cn_ref` と `exp(−4 diff²)` を `T` で計算し、重みを float に丸めて `cn_weight` に保存する。ゼロダンピングでは**倍精度の CN から**重みを作る（`D3:307`）。CN の保存は float のまま（力カーネルの `load_cn_weights` は float の `cn` を読む） |

**倍精度にしない（できなかった）もの**：

- **BJ の経路**は変更せず、ビット同一です（5.1.6）。カーネルとしては `damping` による実行時の分岐で、ゼロダンピング専用のカーネルはありません（カーネル数は 33 のまま、VER-0024 6 節）。
- **大箱の CN カーネル**（`D3:1006-1110`）は、ゼロダンピングでも **float** です（`D3:1085`）。これを double にする試みは、heavy_cluster の小箱との差を 1.14 → 1.40、参照との差を 0.78 → 1.60（上限超過）にして**悪化**したため、元に戻しました [VER-0024 5 節]。
- `g_cn` の float 保存：float に丸めた CN から重みを作る変形は、小箱の heavy_cluster を 0.57 → 0.94 倍（上限比）に悪化させたため採用しませんでした [VER-0024 5 節]。

**採用後の精度（小箱、simple-dftd3 に対して）**：graphite の dV 6.98×10⁻⁶（上限 8.96×10⁻⁶、余裕 22 %）、heavy_cluster 6.03×10⁻⁷（上限 1.06×10⁻⁶、余裕 43 %）、dF の最大 8.83×10⁻⁷（revPBE graphite、下限 1×10⁻⁶、余裕 12 %）。20 ケース中 20 ケースが許容内です。graphite の 9.79×10⁻⁶ のうち約 7.9×10⁻⁶ は、倍精度にしても残る分（長さ定数の規約：GPUMD の `Bohr` 対 CODATA 2018。CN 項は R_cov に約 100 eV の感度）で、実装では取り除けません [VER-0024 1 節]。

**AC-5 の限界（人間が例外として承認、2026-11-06）**：同じ原子を大箱の分岐に複製して小箱と比べたビリアルの差は、ADR-0002 の上限の倍率で graphite 0.45、**heavy_cluster 1.14**、water27 0.02 です。heavy_cluster だけが上限を超えます。BJ（develop のコード）でも同じ系で 1.72 倍なので、ゼロ固有ではなく既存の差です。CN の float 化は主因ではありません（スレッド数 1〜16、箱 50〜90 Å、リスト容量 0、CN をほぼ切った `rc_cn = 0.5` でも 0.70 が残る）。**原因は特定していません** [VER-0024 5 節、DR-003 AC-5、06 章 6.10.4 節]。

**コスト**：レジスタ数（cuobjdump、旧 → 新）は cn_small 32 → 34、force_small 72 → 77、force_large 79 → 82、他は不変で、カーネル数は 33 のままです。1 ステップ全体の zero/BJ は 1.045〜1.064（最終確認）です [VER-0024 6 節]。倍精度の CN だけのコストは、分離して測っていません。

### 5.1.5 ゼロダンピングの `damping` 引数とキーワード構文

`dftd3 <functional> <rc_pot> <rc_cn> [zero|bj]`。構文検査は `DFTD3::parse_damping`（`D3:2036-2056`）で、`NEP::initialize_dftd3` と `NEP_Charge::initialize_dftd3` が呼びます（04 章 4.2 節）。4 トークンなら `bj`、5 番目が `zero` / `bj` 以外ならエラーです。`DFTD3::initialize` は `damping` 引数（既定 `"bj"`）で `dftd3_para.damping` を決め（`D3:1931-1932`）、ゼロダンピングのときだけ起動メッセージに `damping = zero (D3(0))`、`sr6`、`sr8`、`alpha6 = 14, alpha8 = 16` を出します（`D3:2010-2027`）。BJ の出力は従来と同一です（ADR-0003 項目 4 の改訂後）。

## 5.2 ベースライン構造（master）と最適化後の構造

### master の構造

`master`（upstream 3b2c8db8）の `src/force/dftd3.cu`（サブフォルダ再構成の前のパス。upstream/master `aa63ffdd` では `src/force/dftd3/dftd3.cu` で、内容は同一の 1169 行）は、次のような構造でした。下表の「master の `dftd3.cu:n`」は、このファイルの行番号です（現在のフォークのファイルの行番号ではありません）。

| 項目 | master | 出典 |
|---|---|---|

## 5.3 複数スレッド／原子と固定順序の木縮約

### 構成

`num_sub` 個（2 の冪）の連続スレッドが 1 原子 n1 を担当します（`D3:659-662`）。

```cpp
// D3:659-662（add_dftd3_force_small_box）
  const int tid = threadIdx.x;
  const int sub = tid % num_sub;
  const int n1 = blockIdx.x * (blockDim.x / num_sub) + tid / num_sub;
  const bool valid = n1 < N;
```

- 小箱：スレッド `sub` は近傍リストの `sub, sub+num_sub, …` 番目の要素を処理します（`D3:686`）。
- 大箱：スレッド `sub` は、近傍セルの `sub, sub+num_sub, …` 番目のセルを処理します（`D3:1060`、`1187`）。
- 各スレッドは、エネルギー、力 3 成分、ビリアル 9 成分、`dc6_sum`、`dc8_sum` を float のレジスタに累積します。

### 縮約

部分和を共有メモリ `s_red[値の番号][スレッド番号]` に置き、オフセットを `num_sub/2` から 1 まで半分にしながら足し込みます（`D3:613-625`）。

```cpp
// D3:613-625
template <int num_sub, int num_values>
__device__ __forceinline__ void
reduce_sub_large_box(float (*s_red)[BLOCK_SIZE_LARGE_BOX], const int tid, const int sub)
{
  for (int offset = num_sub / 2; offset > 0; offset >>= 1) {
    __syncthreads();
    if (sub < offset) {
      for (int k = 0; k < num_values; ++k) {
        s_red[k][tid] += s_red[k][tid + offset];
      }
    }
  }
}
```

```text
num_sub = 8 の例（sub = 0..7 の部分和 p0..p7）
offset 4:  p0+=p4, p1+=p5, p2+=p6, p3+=p7
offset 2:  p0+=p2, p1+=p3
offset 1:  p0+=p1           → 結果は sub == 0 のスレッドにある
```

足す順序は `num_sub` だけで決まり、スレッドのスケジューリングに依存しません。結果を書くのは `sub == 0` のスレッドだけで、`g_fx[n1] += s_fx` のように**自分の原子の要素へ 1 回だけ**書きます（`D3:762-776`）。つまり、出力の各要素を書くスレッドは 1 つだけで、競合する書き込みがありません。

### 設計上の注意

- `__syncthreads()` を含むため、ブロック内の**全スレッド**がこの関数を呼ぶ必要があります。端数ブロックの無効スレッド（`n1 >= N`）も、原子 0 を読んで（`n1_safe`）ループを実質空にし、縮約には参加して、書き込みだけを省きます（`D3:662-664, 742-744`）。
- 小箱では `num_sub` が最大 128 で、ブロック 128 を割り切る必要があります（`static_assert`、`D3:655-659`）。大箱は最大 16 です。
- 共有メモリは `s_red[15][128]` の float で 7,680 B です。
- `num_sub = 1` のときはブロックを 64 にし、縮約をしません（`num_sub > 1` の分岐、`D3:724`）。このとき累積順序は master と同じです [VER-0004 §1]。
- 同じ構造が D2 にもあります（`SubReduce<NUM_SUB>`、`D2:336-414`。共有メモリ `s_red[13][128]` は double）。

### スレッドを増やしすぎない理由（小箱の走査）

小箱の走査表 [VER-0013]（力カーネル、ms）によれば、N が数千を超えると、`num_sub` を大きくするほど遅くなります。

| N | 既定 | 1 | 4 | 16 | 128 |
|---|---|---|---|---|---|
| 81 | 0.019 | 1.099 | 0.284 | 0.081 | 0.019 |
| 2,187 | 0.144 | 1.384 | 0.381 | 0.144 | 0.188 |
| 8,748 | 0.442 | 1.323 | 0.419 | 0.952 | 0.686 |

理由（コードのコメントと VER-0013 の記述）：カーネルは遅延律速（リスト要素ごとの依存するグローバルロードの連鎖）で、スレッド数を増やすと遅延を隠せますが、多すぎると 1 ワープのリスト読み出しが多くの行に分散して遅くなります（`D3:901-906`）。規則は「`N × num_sub` を SM 数 × 640 以下」にとどめます。

## 5.4 因数分解した C6 重み、float 累積、W < 1e-30 の fallback

### C6 補間の因数分解

D3 の C6 は、参照配位数の格子上の値 `c6_ref[a][b]` を、ガウス重み `L_ab` で補間した値です。重みは

```text
L_ab = exp(-4 (CN_1 − CNref_1[a])²  − 4 (CN_2 − CNref_2[b])²)
     = w_1[a] · w_2[b]            w[k] = exp(-4 (CN − CNref[k])²)
```

と因数分解できます（コードの説明は `D3:57-61`）。master は、ペアごとに `a, b` の二重ループで `exp` を計算していました（最大 25 回）。本フォークでは、次のようにします。

1. CN カーネルが、原子ごとに 5 個の重み `w[k]`（`max_cn = 5`、`num_cn` を超える参照点は 0）を `cn_weight[n·5 + k]` に保存します（`store_cn_weights`、`D3:62-75`）。メモリは 1 原子あたり 20 B（N = 41,472 で 0.83 MB）です [VER-0014]。
2. 力カーネルは、中心原子の重み `w`、`dw = w·(−8·diff)`、およびその和を `load_cn_weights` で 1 回だけ読みます（`D3:86-106`）。
3. ペアごとに `get_c6_factorized`（`D3:109-165`）が、相手原子の重みを 5 個読み、積と和だけで Z、dZ、W、dW を作ります。

```cpp
// D3:140-164（get_c6_factorized の要点）
  float Z = 0.0f;  float dZ = 0.0f;
  for (int a = 0; a < max_cn; ++a) {
    if (a < num_cn_1) {
      float t = 0.0f;
      for (int b = 0; b < max_cn; ++b) {
        if (b < num_cn_2) { t += c6_pair[a * stride_a + b * stride_b] * w2[b]; }
      }
      Z  += cw.w[a]  * t;
      dZ += cw.dw[a] * t;
    }
  }
  float W = cw.sum_w * sum_w2;
```

`W = (Σ w_1)(Σ w_2)` は、因数分解しない場合の `Σ L_ab` と、丸めを除いて等しくなります [VER-0014]。`c6 = Z/W`、`dc6 = dZ/W − c6·dW/W²` です（`D3:161-163`）。`c6_ref` の添字は、元素対 `(z_small, z_large)` について格納されており、`z1 < z2` かどうかで a と b の歩幅を入れ替えます（`D3:136-138`）。

- 両原子の `num_cn` が 1 のときは、`c6 = c6_ref の先頭要素`、`dc6 = 0` の近道があります（`D3:123-125`）。
- 参照データの添字 `z12 = z_small·max_elem − z_small(z_small−1)/2 + (z_large − z_small)`（`D3:695`）で、`c6_ref` は 94 × 95 / 2 = 4,465 対 × 25 = 111,625 個です（導出）。

効果と限界：D3 合計で、水 5,184 が 1.21 倍、クラスター 972 が 1.23 倍、水 41,472 が 1.10 倍、他は 1.02〜1.08 倍で、遅くなる例はありませんでした。水 41,472 の目標（6.0 ms 以下）は未達でした（6.931 → 6.316 ms）。C6 を定数に置き換えた上限（5.59 ms）に届かないのは、C6 の参照表の二重和がペアループに残り、レジスタが 72 から約 80 に増えるためです [VER-0014]。結果は丸めレベルで変わり、AC-1 / AC-2 の許容値内です。

### float 累積

ペアの和（エネルギー `s_pe`、力 `s_fx…`、ビリアル `s_sxx…`、`dc6_sum`、`dc8_sum`）は、スレッドのレジスタ内で **float** で累積します（`D3:670-685`）。最後に、`sub == 0` のスレッドが **double の per-atom 配列に 1 回だけ** `+=` します（`D3:762-774`）。CN は、BJ の小箱（`cn_sum_small_box<float>`、`D3:270`）と、**大箱（BJ でもゼロダンピングでも）**（`cn_temp`、`D3:1041`、`1085`）で float です。**ゼロダンピングの小箱だけ、CN の和を double で行います**（`cn_sum_small_box<double>`、5.1.4 節）。

小箱の最適化の前は、float の項を double の `atomicAdd` で加えていました。float 累積への変更は丸めレベルの変更で、AC-1 の許容値内であることを確認しています（最大の変化は graphite の dE：3.94e-6 → 4.63e-6、許容値は 7.88e-6 [VER-0013]）。

D2 は、DR-004 の R3（ADR-0005 は 2026-11-06 承認、実装と測定は VER-0026 5 節の 2026-11-07）の前は逆で、ペアの項は float、**累積は double** でした（R3 前のコードの行番号は本章から外しました）。R3 以降は、ペアの項は float のまま、累積を **TwoSum で補償した float の和**にし、4 セルごとに double の累積へ足します（`CompensatedSum`、`PairSums`、`FLUSH_CELLS = 4`。サブスレッドの縮約は double のまま、atomic なし）。詳細は 5.6.6 項です。

### W < 1e-30 の fallback（upstream 由来の挙動）

```cpp
// D3:156-164
  float W = cw.sum_w * sum_w2;
  const float dW = cw.sum_dw * sum_w2;
  if (W < 1.0e-30f) {
    c6 = c6_pair[(num_cn_1 - 1) * stride_a + (num_cn_2 - 1) * stride_b];
  } else {
    W = 1.0f / W;
    c6 = Z * W;
    dc6 = dZ * W - c6 * dW * W;
  }
```

`W` が 1e-30 未満になると、最後の参照対の C6 を使い、`dc6 = 0`（CN 依存の力を落とす）とします。この規則は upstream の元のコードと同じで、因数分解の導入前からあります。float の `exp(−4 diff²)` は、CN がどの参照 CN からも約 4.2 以上離れるとアンダーフローするため、極端な CN で誤った C6 が選ばれます。参照実装（simple-dftd3）は倍精度で、より遠くまで正規化した重みを保ち、それを超えると最大 CN の参照を使います。H 原子のように「最後の参照」が最大 CN でない元素では、誤った参照を選びます [UPSTREAM-0001、VER-0017]。通常の NEP89 の MD 系（水、結晶、有機物）では AC-1 の許容値内で影響が出ません。因数分解で挙動は変わっていません [VER-0014、UPSTREAM-0001 冒頭]。

## 5.5 CN カーネルと extra カーネルのリスト共有

### 動機

大箱経路では、CN カーネルと extra カーネルは同じ angular セルリスト、同じ `rc_cn`、同じペア判定を使います。つまり extra カーネルの近傍走査は、CN カーネルの走査の 100% の繰り返しです。受理されるペア 1 つあたり約 4〜4.5 個の候補を訪れます [VER-0015、`D3:962-965` のコメント]。

### 仕組み

CN カーネルは、受理した相手の番号を、スロットごとのリストに保存します。スロットは `(原子 n1, sub)` の組で、`slot = n1·num_sub + sub` です（`D3:1042-1043`）。

```cpp
// D3:1081-1096（find_dftd3_coordination_number_large_box）
          if (d12_2 < rc * rc) {
            ...
            cn_temp += 1.0f / (exp(-16.0f * ((R_cov_1 + R_cov_2) / d12 - 1.0f)) + 1.0f);
            if (num_accepted < list_capacity) {
              g_list[num_accepted * num_slots + slot] = n2;
            }
            ++num_accepted;
          }
  ...
  if (valid && list_capacity > 0) {
    g_list_count[slot] = num_accepted;
  }
```

- リストの配置は `g_list[k·num_slots + slot]` で、同じ `k` のスロット間でメモリが連続（コアレッシング）します。
- `num_accepted` は容量を超えても数え続けるので、`g_list_count` は「実際に受理した個数」で、溢れを検出できます。

extra カーネルは、スロットの個数を読み、**全員が収まった場合だけ**リストを使い、そうでなければセル走査を元通り繰り返します（`D3:1386, 1425-1429`）。

```cpp
// D3:1386、1425-1429（find_dftd3_force_extra_large_box）
  const int num_listed = (valid && list_capacity > 0) ? g_list_count[slot] : -1;
  ...
  if (num_listed >= 0 && num_listed <= list_capacity) {
    for (int k = 0; k < num_listed; ++k) {
      add_pair(g_list[k * num_slots + slot]);
    }
  } else { /* セルを走査して add_pair(...) */ }
```

### 容量・溢れ・同一性

| 項目 | 内容 |
|---|---|
| 容量 | 4.3 節の規則。`int(min(1.5·expected_pairs/num_sub, 4096)) + 8`。256 MB を超えるなら 0（リスト不使用） |
| 溢れ | 容量不足のスロットは走査に戻る。「容量が小さすぎると時間が増えるだけで、精度は変わらない」（`D3:965-967` のコメント）。水 41,472、5,184、Cu 4,000、クラスター 972 の初回ステップで、既定容量では溢れるスロットが 0 でした（他の密度については主張していません）[VER-0015] |

効果：extra カーネル 0.760 → 0.200 ms（水 41,472、3.8 倍）、D3 合計は水 5,184 で 1.04 倍、Cu 4,000 で 1.07 倍、クラスター 972 で 1.28 倍でした。小箱経路のコードは変更していません [VER-0015]。

小箱経路には、同様のリスト共有はそもそも不要です。小箱は完全な近傍リスト `NL_angular` を持ち、extra カーネルがそれをそのまま使うからです。

## 5.6 D2：近傍リストなし、コスト基準のセル数、NUM_SUB スレッド、セル中心相対の float4 候補ループ

### 全体

D2 は、近傍リストを保存せず、分数座標上の**セルリスト**を直接走査します（`D2:30-42` のヘッダコメント）。エネルギー・力・ビリアルは per-atom のレジスタに（R3 以降は補償付き float の和として、4 セルごとに double へ足して。5.6.6 項）累積し、力への `atomicAdd` はありません。同一のカーネルが、セルがカットオフより小さい場合も大きい場合も扱います（周期イメージを含めて近傍セルを訪れる）。全ペアを両方の原子から評価するので、エネルギーは `0.5·φ_sf` ずつ加えます（`D2:550`）。

### 5.6.1 コスト基準のセル数（`choose_cell_counts`、`D2:583-638`）

方向ごとのセル数 `n[d]` の候補は、1 と `floor(kk · width_d / rc)`（`kk = 1..6`、`MAX_CELL_RANGE = 6`）で、各候補は `cbrt(max_cells)` 以下に制限します。すべての組合せ `(n_x, n_y, n_z)` について、次のコストを評価して最小のものを選びます（毎回ホストで実行）。

```text
k_d           = ceil( rc / (width_d / n_d) * (1 + 1e-12) )          （近傍セル範囲）
cells_visited = Π_d (2 k_d + 1)        （非周期方向は min(2 k_d + 1, n_d)）
cost          = N * cells_visited / num_cells  +  3.0 * cells_visited
                └ 訪れる候補原子数（一様密度）    └ セルを訪れるコスト（CELL_VISIT_COST）
```

`CELL_VISIT_COST = 3.0` は、水と Cu、`rc` = 12〜30 Å での、強制セル数での実測時間（40 点）に合わせた値です（フィットの rms 対数誤差 0.14）[VER-0008 §2]。検証は、フィットに使った系に、フィットに使わなかったカットオフ（14、16、18、25）と水 20,736 を加えたものです。

旧規則は固定の `n = floor(2·width/rc)` で、水 648 原子（箱 18.6 Å）では `rc` ≥ 18.6 Å でセル数が 2 から 1 に落ち、全原子が 125 イメージ（`k = 2`）を走査して 16 → 20 Å で時間が 4〜4.8 倍に跳ねました [DES-0002 Phase 6 Stage 1 (c)]。コスト基準にして跳びは解消し、水 648 原子で 1.62 倍（`rc` = 30 Å）、2.28 倍（20 Å）、どの系も 1.03 倍より遅くなりませんでした [VER-0008]。

### 5.6.2 NUM_SUB スレッド（`get_num_sub`、`D2:645-653`）

`NUM_SUB`（最大 32、2 の冪）個の連続スレッドが 1 原子を共有し、各近傍セルで `NUM_SUB` 個おきの原子を処理します（`D2:497`）。縮約は 5.3 節と同じ固定順序の木で、`atomicAdd` を使いません。選択規則は 04 章 4.5 節です。効果：水 648、`rc` = 30 Å で、セル数の変更に上乗せして 9.4 倍（合計 15.2 倍）。D2 の追加時間は N = 648 で 54.3 → 2.92 ms、N = 41,472 で 211 → 117 ms でした [DES-0002 Stage 2、VER-0008]。

### 5.6.3 セル中心相対の float4 候補ループ

候補原子の位置を、**自分のセルの中心からの相対座標**にして `float4` で保持します（`place_atoms`、`D2:280-286`）。ペアベクトルは、次のように作ります。

```cpp
// D2:492-508（dftd2_pair_kernel の候補ループ）
        const float ofx = static_cast<float>(by0 + ox * grid.C[0]);   // セル中心間の変位（double で作り、1 回だけ float に丸める）
        ...
          const float dx = (pj.x - pi.x) + ofx;
          const float dy = (pj.y - pi.y) + ofy;
          const float dz = (pj.z - pi.z) + ofz;
          const float r2 = dx * dx + dy * dy + dz * dz;
          if (r2 >= rc2) { continue; }
```

**誤差の評価**（`D2:37-42`、VER-0009 §1）：オフセット（最大で約 `k·w`、すなわち約 `rc`）を float に丸め、和をもう一度丸めるので、ペアベクトルの各成分の絶対誤差はおよそ `6e-8 × (r + w)`（r はペア距離、w はセル幅）です。これは箱の大きさにも、原点からの距離にも依存しません。近いペアでは、厳密な double ベクトルを 1 回だけ丸めた場合（約 `6e-8·r`）の最大 `(1 + w/r)` 倍になります（例：r = 3 Å、w = 12 Å で約 5 倍、2e-7 → 1e-6 Å）。

| 変形 | AC-1 許容値に対する最大誤差の割合 | 採否 | 出典 |
|---|---|---|---|
| 候補を double（旧） | 0.03〜0.14（float のペア演算由来） | － | VER-0009 §2 |
| 絶対座標の float（`fa`、試験のみ） | 0.29〜0.73、原点から +100 Å の系で **2.53（不合格）**。ペアベクトルが反対称でなく、合力が `Fmax` の 1e-5 に | 不採用 | VER-0009 §2 |
| セル中心相対の float（`fb`） | 最大 0.27（ゲート 1/3 以下）。合力は `Fmax` の 3e-16〜6e-15 程度 | **採用** | VER-0009 §2 |

採用の効果：ペアカーネル 1.49〜1.86 倍（水 648、5,184、Cu 4,000、`rc` = 12〜30 Å の 35 点）、遅くなる例なし、レジスタ 34（変更なし）[VER-0009 §3]。ペアベクトルは i ↔ j で厳密に反対称（同じ float 演算で符号が反転するだけ）なので、合力は丸めの範囲でゼロです（VER-0009 §1）。ペアの項（`r`、`exp`）は float です（累積は R3 以降、補償付き float。5.6.6 項）。シフト項 `φ(rc)`、`φ'(rc)` は初期化時に double で求めて float に落とします（`D2:827-834`）。`trunc plain` のときはシフト項を 0 にします（5.6.5 項）。`rc` 自体も初期化時に一度 float に丸め、カットオフ判定、シフト項、セル探索で同じ値を使います（`D2:778-780`）。

### 5.6.4 決定的な並び

`list_atoms` はセルごとの原子リストを `atomicAdd` で作るため、順序はスケジューリング依存ですが、`place_atoms` は「同じセルで番号が小さい原子の数」を数えて順位にし（`D2:269-271`）、元の番号の昇順に並べ直します。これにより、並べ替え後の順序が決定的になります。`list_atoms` の出力は中間データにとどまります（`dftd2.cuh:83`）。

### 5.6.5 オプション、ペアパラメータ表の構築、QE 互換の表（DR-004、ADR-0004）

**構文とオプション構造体**：`dftd2 <s6> [<cutoff>] [table grimme2006|qe] [trunc sf|plain]`。`DFTD2::Options { bool table_qe; bool trunc_plain; }`（`D2h:31-34`）が選択を持ち、`DFTD2::parse_tokens`（`D2:675-749`）が構文を検査します。`s6` は正の有限値、カットオフは **2 番目のトークンが数のときだけ**カットオフとして読み（`is_number`、`D2:667-673`）、オプションは `table` / `trunc` と値の組で、順序は自由、各 1 回まで、小文字だけです。**`table qe` または `trunc plain` を使うときはカットオフの明示が必須**です（`D2:743-748`。QE のラベルの設定と静かにずれるのを防ぐため、ADR-0004 項目 6、人間の承認）。既定（`table grimme2006`、`trunc sf`、30 Å）の入力は従来と同じ動作で、既定のヘッダ行は不変です（`D2:842-852`。`table = qe`、`trunc = plain` の行は非既定のときだけ。`trunc plain` では 1 行目が `cutoff = %g A` になる）。`DFTD2::find_in_run_input`（`D2:751-767`）が `run.in` の全行から `dftd2` の行を 1 つ探し、`dftd3` との併用をエラーにします。

**ペアパラメータ表の構築（`DFTD2::initialize`、`D2:804-840`）**：型のペアごとに、ホスト側で**倍精度**の `s6c6`（= s6·C6_ij、eV Å⁶）と `R0` を作り、`float4 {s6c6, R0, φ(rc), φ'(rc)}` に落として `pair_param_` に転送します（デバイスのカーネルは `par.x = s6c6`、`par.y = R0`、`par.z = φ(rc)`、`par.w = φ'(rc)` として読む）。

| 設定 | `s6c6` | `R0` |
|---|---|---|
| `table grimme2006`（既定、`D2:823-825`） | `s6 · sqrt(C6_i · C6_j)`（`dftd2para.cuh` の eV Å⁶ の表） | `R0_i + R0_j`（同表、Å） |
| `table qe`（`D2:816-822`） | `s6 · C6_QE[idx] · AUTOEV · BOHR_A⁶`。`C6_QE` は **QE の `c6ab(Zi, Zj, 1, 1, 1)`（両原子の最初の参照点、Eh bohr⁶）**で、`sqrt(C6_i C6_j)` ではない | `1.1 · r0ab[idx]`（Å、`QE_RS6 = 1.1`） |

`idx = zl·(zl+1)/2 + zs`（0 始まりの原子番号、`zs ≤ zl`）で、`dftd2qe_table.cuh` の下三角の詰め込みです（4.1 節）。`trunc sf`（既定）では `φ(rc)`、`φ'(rc)` を倍精度の `phi_dphi`（`D2:108-115`）で求め、`trunc plain` では 0 にします（`D2:827-830`）。**同じカーネルが両方を扱い**、`trunc plain` 専用の分岐はカーネルにありません（`phi_sf = phi − par.z − par.w·(r − rc)` の `par.z = par.w = 0`）。したがって `plain` ではペアが `rc` を横切るときエネルギーに段差が生じます（06 章 6.11.3 節）。元素が表の範囲外（`Z < 1` または `Z > 86`）のペアは NaN を入れ、誤使用が目に見えるようにします（実際には `check_elements` が先にエラーにするので使われない、`D2:810-813`）。

**定数（CODATA 2018、倍精度、`D2:69-79`）**：QE 7.2 の `Modules/constants.f90` の `BOHR_RADIUS_SI = 0.529177210903e-10`、`HARTREE_SI = 4.3597447222071e-18`、`ELECTRONVOLT_SI = 1.602176634e-19` から `AUTOEV = HARTREE_SI / ELECTRONVOLT_SI = 27.211386245988`、`BOHR_A = BOHR_RADIUS_SI·1e10` を作り、`C6[eV Å⁶] = C6[Eh bohr⁶]·AUTOEV·BOHR_A⁶` とします。QE は `r0ab` を `autoang` で割ってから自身の bohr 半径を掛けるため、R0 に相対 4.4×10⁻⁹ の差が出ますが、意図的に無視しています（コメント `D2:72-73`、VER-0025 4 節）。

**`dftd3para.cuh` の float 定数を使わない理由**：`HartreeBohr6 = 0.597527426643772f` は CODATA 2018 から求めた値に対し相対 +8.74×10⁻⁷ 大きく（ADR-0004 項目 3）、そのまま使うとエネルギー、力、ビリアルが QE のラベルに対し系統的にずれます（AC-1 の上限 2×10⁻⁶ の約 44 %）。また、`dftd2.cu` が float の `c6_ref_cpu` と、デバイス専用の `__constant__` な `d3zero_r0ab` に依存しないようにするためです（ADR-0004 項目 3）。このため `dftd2qe_table.cuh` は C6 と r0ab を**倍精度の `static const`** の表として持ち、ホストで換算します。

**生成と照合**：`dftd2qe_table.cuh` は `generate_dftd2qe_table.py` が qe-7.2 のソースから生成します（4.1 節）。QE 7.2 の `c6ab(Zi, Zj, 1, 1, 1)` と `r0ab`（Z ≤ 86）は、GPUMD / dftd3-lib の表と項目ごとに一致し（不一致 0、3741 ペア）、生成ファイルは新規生成および VER-0025 の CSV とバイト単位で同一です [VER-0025 4 節、VER-0026 1 節]。QE 7.2 は `r0ab` と一部の `s6` を単精度のリテラルで持つため、相対 5.9×10⁻⁸（減衰の指数で最大 1.2×10⁻⁶）の差があり得ます。表は 10 進の値で持ち、QE 7.2 の float32 の丸めは再現していません [VER-0026 1 節]。

**元素検査（`DFTD2::check_elements`、`D2:862-892`）**：最初の `compute` で一度だけ（`D2:906-908`）、構造にある原子種について、型の範囲と `1 ≤ Z ≤ 86` を検査し、範囲外の元素名つきでエラーにします。メッセージは表ごとに異なります（`table qe` は「'table qe' parameters cover Z <= 86 (H-Rn) only」、`grimme2006` は「built-in DFT-D2 table covers Z <= 86 (H-Rn) only」、`D2:887-888`）。D3(0) の `check_elements`（5.1.3 項）と同じ設計で、Z ≥ 87 は両方の表で非対応です。

### 5.6.6 補償付き float 累算（R3、ADR-0005）

**動機**：`dftd2_pair_kernel` は、ペアごとにエネルギー 1、力 3、ビリアル 9 の計 13 個の和を作ります。R3 の前はこれを double で累算していました。GA102（RTX A6000）では FP64 が FP32 の 1/64 なので、これがカーネル時間を支配します。N = 41,472 の水で、現行カーネル 6.44 ms に対し、13 個の累算器を float にした**時間測定専用**の変形（精度は未評価）は 1.09 ms（−83 %）でした [VER-0026 4 節]。ただし単純な float の累算は、結果が AC-1 の許容値を満たす保証がないため、ADR-0005 は「float の部分和を決まった順序で double に変換して合成する。半精度と fast-math は使わない。補償付き・分割累算（有限個の項ごとに double へフラッシュ）は、測定した誤差に基づいて選んでよい」と定めました。

**構成**（`dftd2_pair_kernel<NUM_SUB>`、`D2:419-575`）：

| 部品 | 内容 |
|---|---|
| `CompensatedSum`（`D2:295-309`） | `sum`、`err` を持つ。`add(x)` は誤差なしの加算 TwoSum：`t = sum + x; bb = t − sum; err += (sum − (t − bb)) + (x − bb); sum = t`。`value() = double(sum) + double(err)`。コメントの前提：TwoSum は再結合されてはならない（fast-math なしならコンパイラは再結合しない）。項は**丸め済みの float として渡す**（和への縮約融合 = FMA を起こさない）。1 つの和の誤差は、項ごとではなく、和の大きさに対して float の丸め 1 回程度 |
| `PairSums`（`D2:314-332`） | 13 個の `CompensatedSum part[13]` と、13 個の `double total[13]`。添字：0 = `phi_sf` の和（エネルギー）、1〜3 = 力、4〜12 = `dx·fp` の和（xx、yy、zz、xy、xz、yz、yx、zx、zy。`SubReduce` の順序）。`flush()`：`total[c] += part[c].value()` のあと `part[c]` を 0 に戻す |
| `__fmul_rn`（`D2:524-538`） | 力の寄与 `fp = g·dx` とビリアルの積 `dx·fp` などを `__fmul_rn`（丸め付き乗算）で作る。通常の `a*b` だと、コンパイラが `sum + a*b` を FMA に縮約して、`TwoSum` に渡す項が丸め済みでなくなるため |
| `FLUSH_CELLS = 4`（`D2:91`） | 近傍セルを 4 つ処理するたびに `sums.flush()`（`D2:540-543`）。ループ終了後にも 1 回（`D2:548`） |
| 最後の処理（`D2:550-575`） | `e_i = 0.5·total[0]`、`W = −0.5·total[4..12]`（係数は厳密）。**double のまま** `SubReduce<NUM_SUB>` で `NUM_SUB` 個のスレッドを木縮約（共有メモリ `double s_red[13][128]`、`D2:355`）し、`sub == 0` が `g_potential[i] +=`、`g_fx[i] +=`、`g_virial[...] +=` で書く |

**フラッシュの理由**：TwoSum だけだと、1 つの float の和に入る項の数が多くなり、補償の 2 次の誤差が残ります。`FLUSH_CELLS` ごとに double へ足して項数を抑えます。判断の根拠は**正味の力の試験**（Σ F = 0 に対する |ΣF|/max|F|、`rc` = 30 Å、水。試験の上限は 1×10⁻¹²）で、次の測定値です [VER-0026 5 節]。

| 変種 | 正味の力（水、`rc` = 30 Å） | カーネル時間（ms。変種の値は VER-0026 5 節の記載で、測定系の明記はない。旧と採用の値は水 41,472 の値と一致） |
|---|---|---|
| 旧カーネル（double 累算） | 1.5×10⁻¹⁴ | 6.41 ms（水 41,472） |
| TwoSum、フラッシュなし（A3b、**棄却**） | 3.7×10⁻¹² | 1.36 ms（試験の上限 1×10⁻¹² に不合格） |
| 毎セルでフラッシュ | 1.6×10⁻¹⁴ | 1.94 ms |
| **4 セルごと（採用）** | **7.6×10⁻¹⁴** | **1.41 ms** |
| 8 セルごと | 1.3×10⁻¹³ | 1.38 ms |

フラッシュ 1 回のコストは 13 回の double の加算です（`D2:87-91` のコメント。コメントの 8×10⁻¹⁴、4×10⁻¹² は上の値を丸めたもの）。

**決定性**：力への `atomicAdd` はなく、`place_atoms` が原子を元の番号の昇順に並べ（5.6 節）、各スレッドは固定の順序で近傍セルと候補を訪れ、補償付きの和、フラッシュ、`SubReduce` も固定順序です。したがって、同じバイナリ・同じ GPU・同じ `NUM_SUB` で実行ごとにビット一致します（5 系と、凍結出力の 5 構造 × 2 入力で 3 回確認 [VER-0026 5 節]）。他の GPU（`NUM_SUB` が変わり得る）や HIP では未確認です。

**カーネルの入出力**：R3 で変わったのは `dftd2.cu` の内部だけです（`D2:295-332`、`D2:419-575`。VER-0026 5 節）。カーネルの引数は `N`、`num_types`、`Grid`、`rc`（float）、`g_pair`（`float4` の表）、`g_cell`、`g_start`、`g_sorted`、`g_sorted_index` と、出力の `double` 配列 `g_potential`、`g_fx`、`g_fy`、`g_fz`、`g_virial`（`D2:419-435`）で、出力は per-atom の `+=` です。`DFTD2::compute` の宣言（`D2h:61-67`）、キーワード、構文、表、出力は ADR-0004 のままです（ADR-0005 項目 7）。

**精度**：採用した変種（A7_4：補償付き float を 4 セルごとに double へフラッシュ）は、旧カーネルとの差が全ケースで AC-1 の上限の 5×10⁻¹⁰ 以下です。スクリーニングした全変種は各 AC-1 の上限の 50 % 以下でした（4 PTFE 構造 × `qe/plain`・`qe/sf`・`grimme2006/sf`、水 81・648 原子の立方・三斜、rc 12・20 Å、Rn-Rn、H-H、PTFE 40,500）。**旧カーネル自身が上限のうち、エネルギーで最大 7.2 %、力で最大 33.0 %（PTFE 40,500）、ビリアルで最大 28.4 % を使っています**。力の 33.0 % はペアごとの float 演算が決めており（累算ではない）、この余裕は N とともに縮み、今回の変更より前からあります（5.9 節 16 番）[VER-0026 5 節]。

**速度（RTX A6000、nsys のカーネル時間とスロープ法の D2 extra、ms／ステップ）**：水 41,472：カーネル 6.41 → 1.41（−78 %）、extra 7.06 → 1.62（−77 %）、D3 extra 6.66。PTFE 40,500：カーネル 6.31 → 1.31（−79 %）、extra 6.34 → 1.39（−78 %）、D3 extra 5.81。水 5,184：extra 0.95 → 0.54（−43 %）、D3 0.77。ADR-0005 項目 6 の基準（カーネル時間と extra のどちらも 20 % 以上の短縮）を満たしました。N ≥ 40,000 で D2 が D3 より遅くないという目標（AC-7、参考）は sm_86 で達成です。**A100（FP64 = FP32 の 1/2）は未測定**で、依頼元が測定します。そこでの短縮は小さいと見込まれますが、確認していません [VER-0026 5 節、ADR-0005]。

## 5.7 検討して採用しなかった案

### (a) float による前段フィルタ（DES-0001 Phase 7 項目 (vii)、VER-0016）

**案**：大箱の CN カーネルで、候補の座標差を float（セル中心相対）で作り、ガード帯付きで `r < rc` を判定する。通過した候補と帯の内側の候補だけ、倍精度の距離を再計算する。受理ペアの集合と受理ペアの倍精度演算は変えない。

**結果**：ゲート（CN カーネル 1.2 倍以上）を満たさず、**かえって遅くなりました**（水 41,472 で 0.93 倍、水 5,184 で 0.86〜0.92 倍）。`src/` の変更は残していません [VER-0016、DES-0001 項目 (vii) 結果]。

**理由（SIMT の性質）**：全候補の約 22% が受理されます。ワープは 32 スレッドが同時に進むので、あるワープ反復で少なくとも 1 スレッドが受理される確率は `1 − 0.78³² ≈ 99.965%`（導出）で、ほぼすべてのワープ反復が、全レーンについて倍精度の経路を（述語付きで）実行します。前段フィルタは、倍精度の仕事を省けず、float の仕事が上乗せされるだけです。倍精度演算を持たない float 版（`cn_xf32`）の CN カーネルは 0.711 → 0.375 ms でしたが、これは結果が変わる（非同一）変形です。得るには、受理候補のワープ内圧縮（compaction）か、float だけで判定する（結果が変わる）方法が必要でした。前者は最小限の試作を超え、後者は項目の「同一性」要件に反するため、追求しませんでした。

### (b) 半近傍リストと `atomicAdd`

- D3：DES-0001 Phase 5 の原因 C（半リスト、アトミックが必要）は「条件付き（Phases 2-4 の後に、なお正当化される場合のみ）」で、実装した証拠は見つかりませんでした（結果は未記載。本マニュアル作成者による確認）。`atomicAdd` の削除（Phase 7 (i)）の方向とも逆です。小箱では、倍精度アトミック（ペアあたり 15 回）が、スレッド数を増やしたとき N = 8,748 で 1.6 倍のコストになると見積もられていました [VER-0012]。
- D2：DES-0002 Phase 6 Stage 2 (iv)（`atomicAdd` を使う半リスト）は、超越関数の部分が 2% 未満で効果が小さく、決定性を失うため、追求しませんでした [DES-0002 Stage 1 結果、Stage 2 結果]。

### (c) 小箱のセルリスト・パラメータ（DES-0001 Phase 7 項目 (ii)）：保留

小箱の近傍リスト構築は O(N²) で、(i)（力・extra の複数スレッド化）の後は D3 合計の大きな割合を占めます（水 81 で 39%、648 で 77%、2,187 で 72%、8,748 で 94% [VER-0013]）。それでも、(ii)（小箱のセル／リストのパラメータをコスト基準で選ぶ）は、**人間の判断で保留**されました。記録された理由は「AC-4 に必要ない」です [DES-0001 Phase 7 Stage 2 結果]（AC-4 の小箱側の目標 N = 81、648 は (i) で達成済み）。保留であり、却下や不可能の判断ではありません。5.9 節の未解決事項です。

5. 他の GPU（sm_86 以外）、他の CUDA バージョン、HIP での決定性は未確認です。

関連：

- `get_num_sub_small_box_for_device` は、最初の呼び出し時のデバイス（`gpuGetDevice`）の SM 数を静的変数に保存します（`D3:952-957`）。複数 GPU を切り替えるプロセスでは、最初のデバイスの値が使われます（コード読解）。
- D2 の `choose_cell_counts` は一様密度を仮定したコスト推定です。強い不均一（スラブ、孤立クラスター）での最適性は、測定していません。非周期方向がある系では、分数座標の範囲を求めるために毎ステップホストへ同期コピーが入ります（`D2:930-935`）。

## 5.10 まとめ

| 技法 | 目的 | 副作用・限界 |
|---|---|---|
| ブロック／原子 + スキャンによる小箱の近傍リスト | O(N²) 走査の並列化。リストの順序は不変 | 計算量は O(N²) のまま、メモリは 320 kB／原子 |
| 複数スレッド／原子 + 固定順序の木縮約 | 小さな N で GPU を埋める。`atomicAdd` を排除し決定性を得る | 丸めレベルの変化。N が大きいとスレッドを増やすと遅くなる |
| C6 の因数分解（`cn_weight`） | ペアループから `exp` を除く | +20 B／原子、レジスタ増。アンダーフロー挙動は upstream と同じ |
| CN リスト共有 | extra の走査の繰り返しを省く | 最大 256 MB の追加メモリ。溢れたら走査に戻る |
| D2 のコスト基準のセル数 | カットオフ依存の跳びを除く | 一様密度の仮定 |
| D2 のセル中心相対 float4 | FP64 の負荷を下げる | 誤差 `6e-8 (r + w)`。AC-1 の 1/3 以下を確認 |
| D3 の共有減衰ヘルパー `d3_damped_pair` と `d3_zero_term`（DR-003） | BJ とゼロダンピングを同じカーネルで扱い、ゼロの項をどの r でもオーバーフローさせない | BJ の演算順序は不変（ビット同一を確認）。実行時の分岐と、ゼロの `r = 0` 保護。レジスタ増（force_small 72 → 77、force_large 79 → 82） |
| ゼロダンピングの小箱の CN を倍精度（DR-003、VER-0024） | CN 勾配項とペアのビリアル項の相殺による float 誤差を、許容値内に収める | 大箱は float のまま（AC-5 の限界）。1 ステップ全体で zero/BJ = 1.045〜1.064 |
| D2 の QE 互換の表と `trunc plain`（DR-004） | QE の `dftd3_version = 2` のラベルに合わせる | ホストで倍精度に換算（CODATA 2018）。カットオフの明示が必須。Z ≤ 86 |
| D2 の補償付き float 累算（R3、ADR-0005） | FP64 が弱い GPU（GA102）でカーネルを約 78 % 短縮する | 許容値は緩めず、旧カーネルとの差は上限の 5×10⁻¹⁰ 以下。A100 は未測定。フラッシュは 4 セルごと（正味の力の試験から決定） |
