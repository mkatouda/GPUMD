# 第6章 検証

本章では、DFT-D3（最適化版）と DFT-D2 の実装が「何を」「どの程度」確認されているかをまとめます。数値は `specs/verification/VER-xxxx/README.md` の記録から転記しており（各所に出典を付記）、作成者が計算した値は「導出値」と明記します。測定していない事項は 6.9 節に一覧します。

## 6.1 検証の方針：三つを区別する

| 種類 | 問い | この実装での例 |
|---|---|---|
| 検証（verification） | 式は正しく実装されているか | simple-dftd3 や独立な NumPy 実装との一致、有限差分による力・ビリアルの整合性、エネルギー保存 |
| 回帰（regression） | 変更前と同じ結果か | `master` ビルドと開発版バイナリの出力比較（`run_regression.py`）、`pytest` |
| 妥当性確認（validation） | 実験や DFT と合うか | **行っていません**。全ての VER 記録のヘッダに「verification（または regression）、validation ではない」と明記されています |

回帰の一致は物理的な正しさを意味しません。許容値は、合格させるために緩めたり、期待値ファイルを再生成して合わせたりしない方針で運用しています [AGENTS.md]。

## 6.2 D3 の精度（DR-001 AC-1）

**基準**：simple-dftd3（conda-forge の `dftd3-python` 1.7.0、PBE、rational/BJ ダンピング、二体項のみ、ATM 無し、倍精度、同じカットオフ）[VER-0001, VER-0017]。試験は `tests_pytest/test_dftd3_reference.py`、参照値は `tests_pytest/fixtures/dftd3/reference.json`（7 ケース）です。

**許容値の規則**（DR-001 AC-1）：各ケースで次を満たすこと。

- |ΔE| ≤ 2×10⁻⁶ × |E_D3|
- max|ΔV| ≤ 2×10⁻⁶ × max|V_ref|
- max|ΔF| ≤ 1×10⁻⁵ eV/Å
- かつ三つの誤差のそれぞれが、max(未変更コードでの誤差の 2 倍, float 雑音の下限) を超えない。下限はエネルギー 2×10⁻⁶ eV、力 1×10⁻⁶ eV/Å、ビリアル 2×10⁻⁵ eV [`test_dftd3_reference.py:35-53`]。

当初の絶対値の上限（1×10⁻⁵ eV、1×10⁻⁴ eV）は 2026-11-03 に撤回され、相対値になりました [DR-001]。

**ケースごとの誤差**（最適化後のコード、「誤差 / そのケースの許容値」）[VER-0015 `results/accuracy.txt`。VER-0019 のマイナー修正前のコード。小箱経路のケースは当時の HEAD とビット一致]：

| ケース | dE [eV] / 許容 | dF [eV/Å] / 許容 | dV [eV] / 許容 |
|---|---|---|---|
| benzene_dimer（非周期） | 3.68e-07 / 1.53e-06 | 2.12e-08 / 1.00e-06 | 3.66e-07 / 1.27e-06 |
| graphite | 4.60e-06 / 7.88e-06 | 5.16e-07 / 1.00e-06 | 5.32e-06 / 1.31e-05 |
| water27 | 1.67e-06 / 3.30e-06 | 1.89e-08 / 1.00e-06 | 1.81e-06 / 6.07e-06 |
| water27_rc25 | 8.07e-07 / 3.46e-06 | 7.08e-08 / 1.00e-06 | 1.07e-06 / 6.18e-06 |
| water27_tri | 2.22e-06 / 4.32e-06 | 4.94e-08 / 1.00e-06 | 2.16e-06 / 6.62e-06 |
| water_large | 4.81e-05 / 9.64e-05 | 2.09e-07 / 1.00e-06 | 4.64e-05 / 9.22e-05 |
| cu_large | 6.13e-04 / 1.23e-03 | 4.61e-08 / 1.00e-06 | 5.70e-04 / 1.13e-03 |

読み方：

- 許容値は各ケース自身の「未変更コードの誤差の 2 倍（下限付き）」なので、余裕は約 1.7〜1.9 倍です。最も余裕が小さいのは graphite の dE（許容の約 59%、導出値）です。
- 最適化前のコードとの差（cand-base）は小さく、最大でも water_large の dE 8.0×10⁻⁸ eV・dF 1.5×10⁻⁸ eV/Å、cu_large の dE 5.4×10⁻⁷ eV・dF 1.7×10⁻⁸ eV/Å でした [VER-0015]。
- 同じ表の water27_rc25 については、VER-0013 でベースラインの実行ごとのばらつき（1.73×10⁻⁶ と 8.07×10⁻⁷ eV）が約 2 倍あることが記録されています [VER-0013, VER-0015]。
- 最終コード（`0c353281`）に対する `accuracy.txt` は残っていません（上の表は VER-0015 時点）。VER-0019 では 130 原子ケースのビット再現性とサニタイザ（memcheck/racecheck 0 件）を確認しています [VER-0019]。
- スレッド配分（`num_sub`）を強制的に変えた場合も、小箱経路の 4 ケースで AC-1 を満たし、`num_sub = 1` と許容内で一致しました [VER-0013]。
- 参照側の定数（CODATA 2018）と GPUMD の `HartreeBohr6` は相対 +8.7×10⁻⁷ 異なります（導出値）。この差はエネルギーの AC-1 上限（相対 2×10⁻⁶）の約 44% に相当し、上の誤差に含まれていると考えられます（推論）[UPSTREAM-0002 B]。

**未カバーの範囲**：AC-1 の参照ケースには極端な配位数の系が含まれていません。その領域では upstream の `master` を含め simple-dftd3 と大きくずれます（UPSTREAM-0001、01 章 1.10 節）。最適化版は「未変更コードと同じ挙動」を保ちます [DR-001 AC-1 注記]。

### D2 のカットオフ収束（DR-002 AC-3）

基準 rc = 40 Å との差に対する事前登録の基準（T1：エネルギー ≤ 0.5 meV/原子、T2：力 5 / 1 meV/Å、T3：圧力 ≤ 0.02 GPa）を、水・グラファイト・MgO で評価しました。**基準をすべて満たす最小の格子点は 30 Å のみ**で、これが既定値です [VER-0005, DR-002 OQ-4]。

| 系 | ΔE [meV/原子] rc = 12 / 16 / 20 / 25 / 30 Å | ΔP [GPa] rc = 12 / 16 / 20 / 25 / 30 Å |
|---|---|---|
| 水 | 0.893 / 0.363 / 0.174 / 0.077 / 0.034 | 0.0143 / 0.0058 / 0.0028 / 0.0012 / 0.0006 |
| グラファイト | 6.365 / 2.586 / 1.238 / 0.548 / 0.242 | 0.1160 / 0.0471 / 0.0226 / 0.0100 / 0.0044 |
| MgO | 8.910 / 3.623 / 1.735 / 0.768 / 0.340 | 0.1530 / 0.0622 / 0.0298 / 0.0132 / 0.0058 |

[VER-0005]。25 Å ではグラファイトと MgO のエネルギー基準（0.5 meV）を満たしません。尾部の法則は ΔE ∝ rc⁻³ です。

重元素では収束していません：fcc Au（a = 4.078 Å）は 30 Å で 10.109 meV/原子（閉じた式 10.112）、圧力 95.5 MPa。T1 を満たすのは約 82 Å、Pt は約 85 Å です [VER-0007 s3]。

水 648 原子、NEP89、10 ps、0.5 fs、既定 rc 30 Å、**各 1 本の軌道**です [VER-0006 s4, VER-0010 A]。

| 実行 | std [eV] | max-min [eV] | ドリフト [meV/原子/ps] | 出典 |
|---|---|---|---|---|
| NEP89 のみ | 0.0886 | 0.339 | +0.0460 | VER-0006 s4 |
| ＋ dftd2 0.75 | 0.0324 | 0.174 | +0.0148 | VER-0006 s4 |
| NEP89 のみ | 0.0843 | 0.296 | +0.0421 | VER-0010 A |

D2 を加えた場合に悪化していないことは確認できますが、軌道は 1 本ずつで統計処理をしていません。違いは float 版 NEP の実行ごとのばらつきの範囲内であり、**D2 が保存性を改善する証拠ではありません** [VER-0006, VER-0010]。

## 6.4 D3 のエネルギー保存（DR-001 AC-3）

基準は「基準バイナリ（`master`、`3b2c8db8`）と比べて悪化していない」です。誠実な結論は、**雑音の範囲で区別できない**（等しいことの証明ではない）です [DR-001 ヘッダ, VER-0020]。

最終 D3 コード（`0c353281`、CN リスト込み）と `master-base` の比較（NEP89、`dftd3 pbe 12 6`、NEP のみの NVT-BDP 300 K で 5 ps 平衡化後、速度を除いて乱数シードを有効にして 70 本の実行、NaN・クラッシュなし）[VER-0020]。表は「中央値/最悪値」で、比は候補/基準の中央値の比とブートストラップ 95% 信頼区間です。

| 系・長さ・量 | n | 基準 中央値/最悪 | 候補 中央値/最悪 | 比 [95% CI] | MWU p | Wilcoxon p |
|---|---|---|---|---|---|---|
| 水 5184、5 ps（S1）std [eV] | 5 | 0.0596 / 0.1010 | 0.0726 / 0.0931 | 1.22 [0.65, 2.72] | 0.310 | 0.438 |
| 〃 絶対ドリフト | 5 | 0.0062 / 0.0128 | 0.0089 / 0.0110 | 1.44 [0.61, 7.54] | 0.310 | 0.312 |
| 水 648、10 ps（S2）std | 20 | 0.0278 / 0.0662 | 0.0305 / 0.0562 | 1.10 [0.62, 1.52] | 0.756 | 0.985 |
| 〃 絶対ドリフト | 20 | 0.0120 / 0.0342 | 0.0126 / 0.0279 | 1.05 [0.51, 1.80] | 0.968 | 0.956 |
| 水 5184、5 ps（S3）std | 10 | 0.0600 / 0.1054 | 0.0763 / 0.0975 | 1.27 [0.77, 2.07] | 0.427 | 0.625 |
| 〃 絶対ドリフト（meV/原子/ps） | 10 | 0.0065 / 0.0128 | 0.0095 / 0.0119 | 1.45 [0.75, 4.27] | 0.385 | 0.232 |
| Cu 4000、10 ps（S3）std | 5 | 0.0030 / 0.0031 | 0.0030 / 0.0031 | 1.00 [0.95, 1.05] | 0.841 | 0.125 |

（max−min の行を含む全表は VER-0020。S1 は 5 本、S3 は 10 本、水 648 は 20 本、Cu は 5 本）

判定基準（VER-0011 D、VER-0020）：(1) 候補の中央値が大きく、かつ MWU または対 Wilcoxon の p < 0.05 となる量が無いこと、(2) 候補の最悪値 ≤ 基準の最悪値の 2 倍、(3) 水 5184 の S1 では中央値の std とドリフトが基準の 3 倍以内。**すべて満たしました**（最小の p は 0.125、最悪値の比は 0.81〜1.00）[VER-0020]。

統計についての正直な注意：

- 水 5,184 原子では std（1.27）とドリフト（1.45）の点推定値が 1 を上回り、水 648 の先行測定（VER-0011 B）でも 1.30 / 1.50 でした。信頼区間は 1 を含みますが、**水 5,184 原子で最大 約 2 倍（std）・約 4 倍（ドリフト）の悪化は 10 本の実行では排除できません**（CI の上端 2.07 と 4.27）[VER-0020]。
- 同一バイナリ・同一初期条件の実行ごとのばらつきは大きく（10 回で std の最小/中央/最大が 0.0132/0.0452/0.0687、約 5 倍の変動）、観測された基準と候補の差より大きいです [VER-0011 A]。
- `velocity ... seed` は、`model.xyz` に既に速度があると無視されます。そのため、VER-0011 の一部のプロトコル（A）は同一初期条件で GPU の実行ごとの非決定性だけを見たものです。プロトコル B では速度を除いてシードを有効にしています [VER-0011]。

## 6.5 回帰試験・pytest の結果（DR-001 AC-2, DR-002 AC-6）

試験環境：RTX A6000（sm_86）、CUDA 12.3、conda 環境 `py312-gpumd` の Python [VER-0018, AGENTS.md]。非決定性により失敗する既知の 37 ケース（`nvt_bdp`、`npt_scr_iso` など。一覧は AGENTS.md）は、同一バイナリ同士でも失敗するため、回帰ではありません。

その他の確認：

- 小箱経路で `num_sub` を 1〜128 に強制した試験、大箱経路のセルリストが厳密かつ再現可能であること、容量を変えても結果が一致することなどのテストがあります [`test_dftd3_reference.py`]。

## 6.8 AC 以外の確認事項（要点）

- **D2 の入力検査**：Z > 86 の元素（Ac、Th、Pa、U、Np、Pu）を構造に入れると、元素を名指ししてエラーになります。表は第二の解析と全 86 件が一致します（`test_table_equals_dftd3_lib_all_86`）[VER-0003]。
- **D2 の定数**：rc を float に丸めて、シフト項・カットオフ判定・セル探索で一貫して使います。200 Å 超は警告のみ。N = 1 は `gpumd` 自体が拒否します [VER-0007]。
- **D3 のその他の確認**：`num_sub` 強制の各値で試験が合格、加えて 130 原子のケースで `num_sub` 1/64/128 がビット再現しました（独立参照は無し）[VER-0004, VER-0013, VER-0019]。
- 最適化の経緯と却下案は 05 章、速度は 03 章を参照してください。
