# 第6章 検証

本章では、DFT-D3（最適化版、BJ とゼロダンピング D3(0)）と DFT-D2（Grimme 2006 の表と QE 型の表）の実装が「何を」「どの程度」確認されているかをまとめます。DR-001・DR-002 の内容は 6.2〜6.4 節、DR-003（D3(0)）は 6.10 節、DR-004（`dftd2` の `table qe` / `trunc plain` と高速化）は 6.11 節にあります。数値は `specs/verification/VER-xxxx/README.md` の記録から転記しており（各所に出典を付記）、作成者が計算した値は「導出値」と明記します。測定していない事項は 6.9 節に一覧します。

## 6.1 検証の方針：三つを区別する

| 種類 | 問い | この実装での例 |
|---|---|---|
| 検証（verification） | 式は正しく実装されているか | simple-dftd3 や独立な NumPy 実装との一致、有限差分による力・ビリアルの整合性、エネルギー保存 |
| 回帰（regression） | 変更前と同じ結果か | `master` ビルドと開発版バイナリの出力比較（`run_regression.py`）、`pytest` |
| 妥当性確認（validation） | 実験や DFT と合うか | **行っていません**。全ての VER 記録のヘッダに「verification（または regression）、validation ではない」と明記されています |

回帰の一致は物理的な正しさを意味しません。許容値は、合格させるために緩めたり、期待値ファイルを再生成して合わせたりしない方針で運用しています [AGENTS.md]。

## 6.2 D3 の精度（DR-001 AC-1）

**基準**：simple-dftd3（conda-forge の `dftd3-python` 1.7.0、PBE、rational/BJ ダンピング、二体項のみ、ATM 無し、倍精度、同じカットオフ）[VER-0001, VER-0017]。試験は `tests_pytest/test_dftd3_reference.py`、参照値は `tests_pytest/fixtures/dftd3/reference.json`（7 ケース）です。

**許容値の規則**（DR-001 AC-1）：各ケースで次を満たすこと。

- |ΔE| ≤ 2×10⁻⁶ × |E_D3|
- max|ΔV| ≤ 2×10⁻⁶ × max|V_ref|
- max|ΔF| ≤ 1×10⁻⁵ eV/Å
- かつ三つの誤差のそれぞれが、max(未変更コードでの誤差の 2 倍, float 雑音の下限) を超えない。下限はエネルギー 2×10⁻⁶ eV、力 1×10⁻⁶ eV/Å、ビリアル 2×10⁻⁵ eV [`test_dftd3_reference.py:35-53`]。

当初の絶対値の上限（1×10⁻⁵ eV、1×10⁻⁴ eV）は 2026-11-03 に撤回され、相対値になりました [DR-001]。

**ケースごとの誤差**（最適化後のコード、「誤差 / そのケースの許容値」）[VER-0015 `results/accuracy.txt`。VER-0019 のマイナー修正前のコード。小箱経路のケースは当時の HEAD とビット一致]：

| ケース | dE [eV] / 許容 | dF [eV/Å] / 許容 | dV [eV] / 許容 |
|---|---|---|---|
| benzene_dimer（非周期） | 3.68e-07 / 1.53e-06 | 2.12e-08 / 1.00e-06 | 3.66e-07 / 1.27e-06 |
| graphite | 4.60e-06 / 7.88e-06 | 5.16e-07 / 1.00e-06 | 5.32e-06 / 1.31e-05 |
| water27 | 1.67e-06 / 3.30e-06 | 1.89e-08 / 1.00e-06 | 1.81e-06 / 6.07e-06 |
| water27_rc25 | 8.07e-07 / 3.46e-06 | 7.08e-08 / 1.00e-06 | 1.07e-06 / 6.18e-06 |
| water27_tri | 2.22e-06 / 4.32e-06 | 4.94e-08 / 1.00e-06 | 2.16e-06 / 6.62e-06 |
| water_large | 4.81e-05 / 9.64e-05 | 2.09e-07 / 1.00e-06 | 4.64e-05 / 9.22e-05 |
| cu_large | 6.13e-04 / 1.23e-03 | 4.61e-08 / 1.00e-06 | 5.70e-04 / 1.13e-03 |

読み方：

- 許容値は各ケース自身の「未変更コードの誤差の 2 倍（下限付き）」なので、余裕は約 1.7〜1.9 倍です。最も余裕が小さいのは graphite の dE（許容の約 59%、導出値）です。
- 最適化前のコードとの差（cand-base）は小さく、最大でも water_large の dE 8.0×10⁻⁸ eV・dF 1.5×10⁻⁸ eV/Å、cu_large の dE 5.4×10⁻⁷ eV・dF 1.7×10⁻⁸ eV/Å でした [VER-0015]。
- 同じ表の water27_rc25 については、VER-0013 でベースラインの実行ごとのばらつき（1.73×10⁻⁶ と 8.07×10⁻⁷ eV）が約 2 倍あることが記録されています [VER-0013, VER-0015]。
- 最終コード（`0c353281`）に対する `accuracy.txt` は残っていません（上の表は VER-0015 時点）。VER-0019 では 130 原子ケースのビット再現性とサニタイザ（memcheck/racecheck 0 件）を確認しています [VER-0019]。
- スレッド配分（`num_sub`）を強制的に変えた場合も、小箱経路の 4 ケースで AC-1 を満たし、`num_sub = 1` と許容内で一致しました [VER-0013]。
- 参照側の定数（CODATA 2018）と GPUMD の `HartreeBohr6` は相対 +8.7×10⁻⁷ 異なります（導出値）。この差はエネルギーの AC-1 上限（相対 2×10⁻⁶）の約 44% に相当し、上の誤差に含まれていると考えられます（推論）[UPSTREAM-0002 B]。

**未カバーの範囲**：AC-1 の参照ケースには極端な配位数の系が含まれていません。その領域では upstream の `master` を含め simple-dftd3 と大きくずれます（UPSTREAM-0001、01 章 1.10 節）。最適化版は「未変更コードと同じ挙動」を保ちます [DR-001 AC-1 注記]。

## 6.3 D2 の精度と整合性（DR-002 AC-1, AC-4）

> **注意**：6.3 節の D2 の数値（独立実装との一致、有限差分、NVE）は、DR-004 の R3（2026-11-07、float の補償付き累算）の**前**のコードに対する測定です。R3 後の精度は 6.11 節で、既定の入力も AC-1 の許容値の範囲で旧カーネルと一致することを確認しています（下位の桁は変わります）[ADR-0005, VER-0026 5 節]。

### D2 のカットオフ収束（DR-002 AC-3）

基準 rc = 40 Å との差に対する事前登録の基準（T1：エネルギー ≤ 0.5 meV/原子、T2：力 5 / 1 meV/Å、T3：圧力 ≤ 0.02 GPa）を、水・グラファイト・MgO で評価しました。**基準をすべて満たす最小の格子点は 30 Å のみ**で、これが既定値です [VER-0005, DR-002 OQ-4]。

| 系 | ΔE [meV/原子] rc = 12 / 16 / 20 / 25 / 30 Å | ΔP [GPa] rc = 12 / 16 / 20 / 25 / 30 Å |
|---|---|---|
| 水 | 0.893 / 0.363 / 0.174 / 0.077 / 0.034 | 0.0143 / 0.0058 / 0.0028 / 0.0012 / 0.0006 |
| グラファイト | 6.365 / 2.586 / 1.238 / 0.548 / 0.242 | 0.1160 / 0.0471 / 0.0226 / 0.0100 / 0.0044 |
| MgO | 8.910 / 3.623 / 1.735 / 0.768 / 0.340 | 0.1530 / 0.0622 / 0.0298 / 0.0132 / 0.0058 |

[VER-0005]。25 Å ではグラファイトと MgO のエネルギー基準（0.5 meV）を満たしません。尾部の法則は ΔE ∝ rc⁻³ です。

重元素では収束していません：fcc Au（a = 4.078 Å）は 30 Å で 10.109 meV/原子（閉じた式 10.112）、圧力 95.5 MPa。T1 を満たすのは約 82 Å、Pt は約 85 Å です [VER-0007 s3]。

## 6.4 D3 のエネルギー保存（DR-001 AC-3）

基準は「基準バイナリ（`master`、`3b2c8db8`）と比べて悪化していない」です。誠実な結論は、**雑音の範囲で区別できない**（等しいことの証明ではない）です [DR-001 ヘッダ, VER-0020]。

最終 D3 コード（`0c353281`、CN リスト込み）と `master-base` の比較（NEP89、`dftd3 pbe 12 6`、NEP のみの NVT-BDP 300 K で 5 ps 平衡化後、速度を除いて乱数シードを有効にして 70 本の実行、NaN・クラッシュなし）[VER-0020]。表は「中央値/最悪値」で、比は候補/基準の中央値の比とブートストラップ 95% 信頼区間です。

| 系・長さ・量 | n | 基準 中央値/最悪 | 候補 中央値/最悪 | 比 [95% CI] | MWU p | Wilcoxon p |
|---|---|---|---|---|---|---|
| 水 5184、5 ps（S1）std [eV] | 5 | 0.0596 / 0.1010 | 0.0726 / 0.0931 | 1.22 [0.65, 2.72] | 0.310 | 0.438 |
| 〃 絶対ドリフト | 5 | 0.0062 / 0.0128 | 0.0089 / 0.0110 | 1.44 [0.61, 7.54] | 0.310 | 0.312 |
| 水 648、10 ps（S2）std | 20 | 0.0278 / 0.0662 | 0.0305 / 0.0562 | 1.10 [0.62, 1.52] | 0.756 | 0.985 |
| 〃 絶対ドリフト | 20 | 0.0120 / 0.0342 | 0.0126 / 0.0279 | 1.05 [0.51, 1.80] | 0.968 | 0.956 |
| 水 5184、5 ps（S3）std | 10 | 0.0600 / 0.1054 | 0.0763 / 0.0975 | 1.27 [0.77, 2.07] | 0.427 | 0.625 |
| 〃 絶対ドリフト（meV/原子/ps） | 10 | 0.0065 / 0.0128 | 0.0095 / 0.0119 | 1.45 [0.75, 4.27] | 0.385 | 0.232 |
| Cu 4000、10 ps（S3）std | 5 | 0.0030 / 0.0031 | 0.0030 / 0.0031 | 1.00 [0.95, 1.05] | 0.841 | 0.125 |

（max−min の行を含む全表は VER-0020。S1 は 5 本、S3 は 10 本、水 648 は 20 本、Cu は 5 本）

判定基準（VER-0011 D、VER-0020）：(1) 候補の中央値が大きく、かつ MWU または対 Wilcoxon の p < 0.05 となる量が無いこと、(2) 候補の最悪値 ≤ 基準の最悪値の 2 倍、(3) 水 5184 の S1 では中央値の std とドリフトが基準の 3 倍以内。**すべて満たしました**（最小の p は 0.125、最悪値の比は 0.81〜1.00）[VER-0020]。

統計についての正直な注意：

- 水 5,184 原子では std（1.27）とドリフト（1.45）の点推定値が 1 を上回り、水 648 の先行測定（VER-0011 B）でも 1.30 / 1.50 でした。信頼区間は 1 を含みますが、**水 5,184 原子で最大 約 2 倍（std）・約 4 倍（ドリフト）の悪化は 10 本の実行では排除できません**（CI の上端 2.07 と 4.27）[VER-0020]。
- 同一バイナリ・同一初期条件の実行ごとのばらつきは大きく（10 回で std の最小/中央/最大が 0.0132/0.0452/0.0687、約 5 倍の変動）、観測された基準と候補の差より大きいです [VER-0011 A]。
- `velocity ... seed` は、`model.xyz` に既に速度があると無視されます。そのため、VER-0011 の一部のプロトコル（A）は同一初期条件で GPU の実行ごとの非決定性だけを見たものです。プロトコル B では速度を除いてシードを有効にしています [VER-0011]。

その他の確認：

- 小箱経路で `num_sub` を 1〜128 に強制した試験、大箱経路のセルリストが厳密かつ再現可能であること、容量を変えても結果が一致することなどのテストがあります [`test_dftd3_reference.py`]。

## 6.10 D3(0)（ゼロダンピング）の検証（DR-003）

種類の区別：以下は**検証**（simple-dftd3 との一致、有限差分、変更前のバイナリとの比較）と**回帰**（BJ のビット一致）で、DFT や実験との比較（妥当性確認）ではありません [VER-0024 ヘッダ]。コードは `wt-d3-zero`（develop `86899ba2` + ゼロダンピング `337a73c9` + 小箱の CN を double に `c200f20c`）で、RTX A6000（sm_86）、CUDA 12.3.107 での測定です [VER-0024]。

### 6.10.1 パラメータの出典（AC-7、VER-0023）

- 表の出典：dftd3-lib（コミット `3c99ee9…`、DFTD3 V3.1 Rev 1 の再配布）の `lib/core.f90`。`r0ab` は `setr0ab` の 4465 個（= 94×95/2）、汎関数パラメータは `setfuncpar` の `version.eq.3`（ゼロダンピング）のブロックです。スクリプト `gen_d3zero_tables.py` が生成し（手入力なし）、個数・対称性・重複なしを検査します [VER-0023 1・3 節]。
- 独立な照合：simple-dftd3 1.7.0（`dftd3` Python バインディング）。**原論文（Grimme et al. 2010）は読んでいません**（ネットワークなし）。パラメータは二つの独立なソフトウェア実装に対して検証したものです [VER-0023 1 節]。
- 結果（`crosscheck_results.txt`）[VER-0023 4 節]：

| 確認 | 結果 |
|---|---|
| A：生成した r0ab 対 dftd3-lib の実行時の値（8836 個） | 不一致 0（10 進値との最大差 5.9×10⁻⁸ は float32 の丸め） |
| B：パラメータ対 dftd3-lib の `setfuncpar`（59 の汎関数・版 × 5） | 不一致 0 |

| E1：式（生成した表）対 simple-dftd3 のエネルギー（Z ≤ 86） | 最大相対 4.5×10⁻¹¹ |
| E2：式（float32 の表）対 dftd3-lib のエネルギー | 最大相対 2.1×10⁻⁷（lib の C6/C8 が simple-dftd3 とビット同一でないため） |

- 定数：dftd3-lib の bohr 定数（0.52917726）と simple-dftd3 の定数（実質 CODATA 2018）が異なり、$\alpha = 14/16$ のため減衰の遷移領域（r ≈ R0）でエネルギーに最大 1.5×10⁻⁶ の相対差を生みます。GPUMD は BJ と同じ `Bohr` を使うので、この差は後述の基準値に**含まれています**（ADR-0003 項目 9）[VER-0023 2 節]。dftd3-lib の float32 リテラル（10 進の公表値からの差は入力で最大 6×10⁻⁸、減衰したエネルギーで最大 2.2×10⁻⁶）のため、dftd3-lib を厳しいオラクルには使いません [VER-0023 6 節]。

### 6.10.2 simple-dftd3 に対する精度（AC-1、VER-0024 1 節）

- 基準：simple-dftd3 の `ZeroDampingParam`、二体項、倍精度、`tests_pytest/fixtures/dftd3_zero/reference.json`。許容値は ADR-0002 の規則（6.2 節）で、PBE に加え revPBE、BLYP、B3LYP、TPSS を含む 20 ケース [VER-0024]。
- BJ 用に暫定的に導出した許容値では、ビリアルだけが 2/20 ケースで不合格でした（pbe:graphite 9.79×10⁻⁶ eV 対 8.96×10⁻⁶、pbe:heavy_cluster 2.05×10⁻⁶ 対 1.06×10⁻⁶。ADR-0002 の上限は変更せず）。同じ系での BJ の誤差と zero の誤差は同程度（dV の比 0.35〜1.84）で、3 回の実行は決定的でした [VER-0024 1 節]。
- **採用した対策**：小箱の配位数カーネルを **double** にする（`zero` のときのみ。BJ の経路は変えず、ビット同一）。理由と根拠：倍精度 NumPy の診断で、配位数の勾配項とペアのビリアル項が相殺し（graphite の xx で −3.427 + 3.413 = −0.0142、項の絶対値の和／合計が最大 1331）、float の累算、ペア項の精度、C6 補間は主因ではなく、**単精度の小箱 CN カーネルが主因**でした。graphite の 9.79×10⁻⁶ のうち約 7.9×10⁻⁶ は、double にしても基準値から残る分（長さ定数の規約の違い：GPUMD の `Bohr` 対 simple-dftd3 の CODATA 2018。CN 項は R_cov に対して約 100 eV の感度）で、float 由来は約 1.9×10⁻⁶ です [VER-0024 1 節]。
- 採用後の結果：graphite の dV 6.98×10⁻⁶（上限 8.96×10⁻⁶、余裕 22 %）、heavy_cluster 6.03×10⁻⁷（上限 1.06×10⁻⁶、余裕 43 %）、dF の最大 8.83×10⁻⁷（revPBE graphite、下限 1×10⁻⁶、余裕 12 %）。**20 ケース中 20 ケースが許容内**です [VER-0024 1 節]。
- **限界**：graphite の余裕は長さ定数の規約に依存し、実装では取り除けません。大箱の CN カーネルは変更していません（大箱のケースは合格）[VER-0024 1 節]。レビューで確認した結果、定数の再スケールをしない参照を作ると r/R0 が約 8.8×10⁻⁸（α = 14 のダンピングで約 1×10⁻⁶）ずれて現状より悪くなるため、追加の参照は作っていません [VER-0024 5 節]。

### 6.10.3 試験と力・ビリアルの整合性（AC-2、AC-4、AC-4b、AC-5 の一部）

`pytest -q test_dftd3_zero.py` 単体で **85 passed（649 s）**。BJ のビット一致（凍結出力）、解析・エラー（ADR-0003、DR-003 D5）、有限差分、小箱／大箱の一致、微小な r を含みます。共有 GPU で一度だけ出た一過性の失敗は、占有した GPU では再現せず、原因は特定していません [VER-0024 2 節]。同時に `test_dftd3_reference.py` 24、`test_dftd2_reference.py` 97、`test_dftd2_consistency.py` 4、`test_dftd2_src_table.py` 3 も合格しました。

### 6.10.4 AC-5 の限界：小箱経路と大箱経路の差（承認済みの例外）

- 同じ原子を大箱の分岐に複製して小箱の結果と比べたビリアルの差（ADR-0002 の上限に対する倍率、採用コード）：graphite 0.45、**heavy_cluster 1.14**、water27 0.02。**heavy_cluster だけが上限を超えています**。
- **BJ（develop のコード、DR-003 では未変更）でも同じ系で 1.72 倍**です。したがって zero 固有の問題ではなく、参照ビリアルが小さく項の相殺が強い系での、小箱と大箱の経路の既存の差です。
- 大箱の CN カーネルも double にする試みは、heavy_cluster の小箱との差が 1.14 → 1.40、参照との差が 0.78 → 1.60（上限超過）となり、**悪化したため元に戻しました**。CN の float 化は主因ではありません：差は 1〜16 スレッド/原子、箱 50〜90 Å、リスト容量 0 で変わらず、CN をほぼ切った状態（rc_cn = 0.5）でも 0.70 が残りました。float の CN から重みを作る案も、小箱の heavy_cluster を 0.57 → 0.94 倍に悪化させたため採用しませんでした [VER-0024 5 節]。
- **原因は特定していません**（候補：小箱の近傍リストでの位置の float 丸め、大箱経路の float の差と `apply_mic`）。**既知の限界として記録し、調査は別課題（DR-001 の領域）としました。人間が例外として承認しました（2026-11-06）** [DR-003 AC-5]。
- 測定した範囲では、経路間の差は上限の 1.14 倍（heavy_cluster）が最大で、BJ の 1.72 倍より小さい値です。参照ビリアルが小さく項の相殺が強い系で経路による差が出うることは、BJ と共通の既知の事項です（上記の測定以外の系は未測定）。

## 6.11 `dftd2` の QE 互換テーブル・単純打ち切り・高速化の検証（DR-004）

種類の区別：以下は**検証**（NumPy 参照、依頼元の参照データ、QE のソースの読解、QE 7.6-dev の実行との比較）と**回帰**（凍結出力）です。**QE 7.2 のバイナリはここで実行していません**。妥当性確認（DFT・実験との比較）ではありません [VER-0025, VER-0026 ヘッダ]。コードは `wt-d2-qe`（R1/R2 は `c3257df2`、R3 は `e1036a4e`）です。

### 6.11.1 パラメータと式の出典（AC-3、VER-0025）

- 出典：QE のタグ `qe-7.2`（コミット `b4c5e8de`）の `dft-d3/pars.f90`（C6）と `core.f90`（`setr0ab`、`setfuncpar`、`pbcedisp`、`pbcgdisp`）。`git show` で読み、リポジトリは変更していません。
- 式（`version == 2`）：rs6 = 1.1、s18 = 0、alp = 20、C6 = `c6ab(Zi,Zj,1,1,1)`（最初の参照点）、R0 = 1.1 × `r0ab`、カットオフ sqrt(9000) bohr（= 50.2 Å、シフトなしのハードカットオフ）、i = j のイメージ（τ ≠ 0）は 1/2 倍。三体項は QE 側で無効（`dftd3_threebody = .false.`）。CN、C8、r2r4 は使いません。**INPUT_PW の「Original Grimme-D2 parametrization」は不正確**で、ソースが計算するのは「D2 の式に D3 の表」です [VER-0025 2 節]。

| Stage 3：pw.x 7.6-dev、CF4（9 Å の三斜セル）、`dftd3_version=2`、rc = sqrt(9000) bohr | エネルギー相対 4.6×10⁻⁸（差 1.6×10⁻⁹ eV、0.0350 eV 中）、力相対 4.6×10⁻⁸（最大差 1.5×10⁻⁹ eV/Å）、応力相対 2.7×10⁻⁸ |

- Stage 3 の残差は、QE が `r0ab` を 0.52917720859（`dft-d3/common.f90`）で割ってから自身の bohr 半径を掛けること（R0 が 1 + 4.37×10⁻⁹ 倍）で**完全に説明されました**（R0 を 1.000000004371 倍した参照で、エネルギー差 +1.2×10⁻¹² eV）。GPU 実装ではこの 4.4×10⁻⁹ を意図的に無視します（ADR-0004、ゲート 2×10⁻⁶ よりはるかに小さい）。QE 7.2 は `r0ab` を単精度リテラルで持つので、7.2 との一致は相対 1×10⁻⁶ 程度までと見込まれます。Stage 3 は 7.6-dev（倍精度リテラル）での実行で、7.2 の float32 の効果は実行されていません [VER-0025 4・7 節]。
- **定数の決定**（ADR-0004 項目 3）：`dftd3para.cuh` の `HartreeBohr6` は CODATA 2018 に対し相対 +8.74×10⁻⁷ ずれ、そのまま使うと E、F、ビリアルが依頼元のラベルに対して系統的にずれます。そのため `table qe` の C6 は、QE 7.2 の定数（CODATA 2018）を使ってホストで倍精度に換算します [VER-0025 5 節, ADR-0004]。
- テーブル：`src/force/dftd2qe_table.cuh`（倍精度、Z ≤ 86、3741 ペア）は、生成スクリプト `tools/Miscellaneous/dftd2/generate_dftd2qe_table.py` による qe-7.2 のソースからの新規生成、および VER-0025 の CSV と**バイト単位で同一**です。拡張テストは 3741 個すべての C6 と r0ab を、CSV と照合し、QE 7.2 のソースが読める環境では、ソースの独立な再解析（生成スクリプトとも VER-0025 の抽出スクリプトとも別方式）とも照合します [VER-0026 1・2 節]。

### 6.11.2 参照値に対する精度（AC-1、VER-0026 2 節）

- 依頼元の参照データ（`tests_pytest/fixtures/dftd2_qe/`、PTFE の 4 構造、rc = 12 Å、s6 = 0.75）に対する相対誤差（上限：エネルギー 2×10⁻⁶、ビリアル 2×10⁻⁶、力 1×10⁻⁵）：`qe/plain` はエネルギー 2.5×10⁻⁹〜6.4×10⁻⁸、力 9.6×10⁻⁷〜1.25×10⁻⁶、ビリアル 3.3×10⁻⁷〜3.8×10⁻⁷。`qe/sf` はエネルギー 4.1×10⁻⁹〜6.7×10⁻⁸、力 9.7×10⁻⁷〜1.25×10⁻⁶、ビリアル 3.5×10⁻⁷〜4.0×10⁻⁷。
- 最悪ケースのペア（拡張テスト）：Rn-Rn の plain はエネルギー 0.4 %、ビリアル 15 %、力 13 %（上限に対する割合）。H-H の plain は 5.7 %、18 %、13 %。
- 混合元素（H、C、N、O、Si、Cl、Rn、Z = 1/86 のペア）、非周期・周期、plain と sf：上限内。
- 境界：ちょうど rc のペアは除外（E = 0.0）、rc = d + 1×10⁻⁴ では含まれる（QE は r² > rthr のみ除外するので、差は無視できる。文書化済み）。
- 4×4×2 の複製で原子あたりのエネルギーと力が一致。`qe/plain` と `qe/sf` の力・ビリアルの有限差分が合格（`plain` の試験系では rc が 0.3 Å 以上のギャップに入るようにした疎な系）。
- パーサとエラー（ADR-0004 項目 1、2、4、6）：有効な形式、オプションの順序、`table qe`・`trunc plain` でのカットオフ明示の必要性、不明・重複トークン、大文字小文字、`table qe` の Z ≥ 87（元素名つき）、旧形式、`dftd3` との排他：すべて合格。

### 6.11.3 `trunc plain` の NVE（AC-5、参考値）

PTFE 2×2×1（180 原子）、NEP89 + `dftd2 0.75 12 table qe`、NVT-BDP 5 ps の後に NVE 20 ps、0.5 fs、各モード 3 シード。全エネルギーの傾きは plain で |傾き| ≤ 2×10⁻⁴ meV/原子/ps、sf で ≤ 1×10⁻⁴（ゼロと区別できない）。標準偏差は plain で 5.1〜5.7×10⁻⁴ eV、sf で 4.9〜5.1×10⁻⁴ eV（plain がわずかに大きいが、3 シードでは断定できない）。ペアが rc を横切るたびの段差 7.4×10⁻⁶ eV（= 0.75 × 49.113 × 0.597527/12⁶）は、1 ステップ当たりのノイズ（中央値 9×10⁻⁵ eV）に埋もれ、**系統的なドリフトは見えませんでしたが、証明ではありません**。力の段差は rc で約 6|φ|/rc = 3.7×10⁻⁶ eV/Å です [VER-0026 3 節]。

### 6.11.4 R3（補償付き float 累算）の精度と決定性（ADR-0005、VER-0026 5 節）

- 方針（ADR-0005）：結果は float の丸めの水準で変わってよいが、倍精度の NumPy 参照（`tests_pytest/dftd2_reference.py`）と依頼元のデータに対する DR-002 AC-1 の許容値（エネルギー・ビリアル相対 2×10⁻⁶、力 1×10⁻⁵）の範囲に収めます。**許容値は緩めません**。参照値は再生成しません。半精度と fast-math は使いません。atomic なし、固定の縮約順序で、実行ごとのビット一致を保ちます。
- スクリーニングした全変種は、各 AC-1 の上限の 50 % 以下でした（4 PTFE 構造 × `qe/plain`・`qe/sf`・`grimme2006/sf`、水 81・648 原子の立方・三斜で rc 12・20 Å、Rn-Rn、H-H、PTFE 40,500）。**採用した変種（A7_4：補償付き float を 4 セルごとに double へフラッシュ）は、旧カーネルとの差が全ケースで上限の 5×10⁻¹⁰ 以下**です。旧カーネル自身が上限のうち、エネルギーで最大 7.2 %、力で最大 33.0 %（PTFE 40,500。ペアごとの float 演算が決めており、累算ではない。この余裕は N とともに縮み、今回の変更より前からある）、ビリアルで最大 28.4 % を使っています。
- 棄却：フラッシュなしの TwoSum（A3b）は、正味の力の試験（|ΣF|/max|F| の上限 1×10⁻¹²）に不合格（rc = 30 Å で 3.7×10⁻¹²、旧カーネル 1.5×10⁻¹⁴）。毎セルのフラッシュは 1.6×10⁻¹⁴ だが遅い（1.94 ms）。4 セルごと（採用）は 7.6×10⁻¹⁴（1.41 ms）、8 セルごとは 1.3×10⁻¹³（1.38 ms）。
- 決定性：実行ごとのビット一致（3 回）を 5 系で、および凍結出力の 5 構造 × 2 入力で確認。
- ADR-0005 項目 5 に従う試験方針：(a) 新バイナリの既定の入力の出力を**旧**凍結出力（develop `af269060`）と AC-1 の水準で比較（エネルギー差 0、ビリアル ≤ 1.7×10⁻¹⁵、力 ≤ 9.4×10⁻¹⁵ の相対差。上限の 1×10⁻⁹ 以下）。(b) 新凍結出力（`default_frozen.json`。旧ファイルは `default_frozen_pre_r3.json` として保存）に対する実行ごとのビット比較。凍結出力は**一度だけ**再生成する承認（2026-11-06、理由：累算の精度が下位の桁を変えるため）に基づきます。実際には中間のスクラッチカーネル（フラッシュなし、コミットなし）で一度生成した後、最終カーネルで再生成しました。人間には報告済みで、ADR-0005 の「一度」を「変更ごとに一度」と解釈しています。他の期待値や許容値は編集していません。**前例にはしません**。
- NVE（参考）：PTFE 2×2×1（180 原子）、`dftd2 0.75 12 table qe trunc sf`、NVT 5 ps の後に NVE 20 ps、シード 1〜3、旧対新：E_tot の傾き −0.0001〜−0.0005 対 −0.0003〜−0.0004 meV/原子/ps、標準偏差 0.011〜0.012 対 0.011〜0.013 meV/原子。区別できません。

### 6.11.5 既定の互換性（AC-2）と限界

- `dftd2 0.75` と `dftd2 0.75 12` の出力は、R1/R2 の変更では変更前のバイナリ（develop `af269060`）とビット同一（凍結出力を 3 回再現、D2 に atomic はない）、5 構造。既定の入力では `table`/`trunc` のヘッダ行を出しません。R3 以降は 6.11.4 のとおり AC-1 の水準での一致に置き換わりました [VER-0026 2・5 節]。
- 限界：QE 7.2 のバイナリは実行していません。依頼元の QE 7.2 との比較（エネルギー・力は印字桁、応力は 0.01 kbar、PTFE）が 7.2 の証拠であり、再現していません [VER-0025 7 節]。Stage 3 は 5 原子の分子（応力は 0.15 kbar）の 1 系で、密な結晶には及びません。A100 での速度と精度は未測定です。マニフェストのケースは未追加です [VER-0026 6 節]。
